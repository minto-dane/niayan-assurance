# ディストリビューション基盤 — 境界を明示した統合

本版は既存の3コードベースにホスト受入れ、サービス構成、ネットワーク変更、起動評価、全体系構成、資格証拠の検査を追加するソース配布です。起動可能なISO、完成したディストリビューション、検証済みコンパイラ成果物または本番認定ではありません。

## 管理責任

|対象|正本／実行主体|今回の統合|
|---|---|---|
|パッケージと配布ファイル|pkgcore、既存RPM配布基盤|カーネル・initramfs・ドライバを含む組合せ検査|
|サービス・cgroup|systemd、クラスタ資源は既存クラスタ管理器|依存グラフ・起動停止順・資源予算・再起動責任者|
|ネットワーク|NetworkManager|永続的な変更状態＋期限付きcheckpoint＋独立した経路確認|
|起動|署名付き既存起動チェーン|試験起動の健全性・安定時間・信頼済み復旧候補の評価|
|ホスト能力|各機能の観測器|Unknown/Satisfied/Violatedを区別した新規操作の受入れ|
|配布認定|独立したビルド・審査・運用主体|同じsource/binary/contract/platformへの署名付き証拠|

PID 1、ファイルシステム、ネットワークスタック、暗号原語、分散合意、DBを新作しません。通常のmutable Linuxを使い、管理対象への書込み責任を一つにします。オブザーバー、クラスタ管理器、systemdが同じサービスを独立して無限再起動させる構成は禁止です。

## 新しい操作に対する接続順

```
リリース証拠・ローカル方針・署名
   -> ホスト受入れと構成検査
   -> 停止確認／クラスタ予算／変更認可
   -> 意図・回復データ・監査記録の永続化
   -> 独立した受入れ記録への比較更新
   -> 操作直前の再認可と正確な対象照合
   -> 既存の実行アダプター
   -> 同じ操作IDについて結果観測
   -> 導入・稼働・安定・承認を個別に記録
```

この順序は全既存ワーカーへ自動接続されたわけではありません。新しいgeneric SDKでは認可・観測・独立アンカーを必須引数とし、常にTrueを返す既定実装を付けていません。純粋な検査器へ渡すAuthenticated等のBooleanは信頼済みアダプター境界で成立させる事実で、外部JSONの自己申告をそのまま代入してはいけません。

## 導入手順

1. 一つのサポート中RPMディストリビューション／リリース／署名方針／カーネル系列を選びます。独自リポジトリ混在はしません。
2. 非特権・隔離ビルド環境で4リポジトリを独立ビルドします。契約コピーの照合は省略しません。
3. Ada試験、GNATprove、cross-repository試験を実施します。成功証拠は正確なバイナリ集合と環境へ結び付けます。
4. まず読み取り専用hostctlを使用します。UnknownをSatisfiedへ置換するためにSecure Boot、LSM、TLS、監査を無効化してはいけません。
5. 検証VM／別ディスクの管理ルートでファイル変更・復旧試験を行います。ネイティブRPMDBとホスト/の所有権移行は未完成です。
6. 独立した管理経路を残し、NetworkManagerのcheckpoint対象と副作用の範囲を実機で確認します。
7. 起動候補と復旧候補を同じ信頼方針で準備し、旧データとの互換性を確認します。新カーネル導入だけで試験起動成功とはしません。
8. 複数ノードでは隔離、クォーラム、書込み所有権、データ復旧、管理器交代、ネットワーク分断を検査してから適用範囲を拡大します。

## 保証の前提

SPARK部分は契約付きソースです。GNATprove未実行です。runtimeはAdaのSPARK_Mode OffでLinux x86_64／FFIを使います。Linux、systemd、NetworkManager、ストレージの永続化、暗号、外部観測、物理fencing、試験報告の真実性は自動的に形式証明されません。

`platform/component-map.json` は完成済みと未接続を機械可読に区別します。既存カーネルの供給遅延や実機故障は管理ソフトだけでは解消しません。OS全体の安全性と、ある契約に対する検査結果を区別してください。
