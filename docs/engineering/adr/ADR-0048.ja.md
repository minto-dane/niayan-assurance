# ADR-0048: XFS永続領域と健全性責任の分離

状態: proposed-for-review。独立審査・本番資格化は未完。2026-09-07。ADR-0045を置換する。

## 背景

Niaの正しさをFS内スナップショットへ依存させない。従来のBtrfs root/ext4 dataの選択より、永続領域の実装と運用工具を統一し、XFSのmetadata相互参照、online scrub/repair、Linux 7系healthイベントを活用する方針を採る。

## 決定

全ディスク永続領域をXFSとし、ESP/volatile/仮想FSを例外にする。rootとcatalogは同一XFS上で論理世代を共有し、control/trust/objects/secrets/log/data等は別LVとする。スナップショットは正しさの必要条件でない。メタデータ修復と内容認証を別契約にする。

## 代替案

Btrfsは内容チェックサム・冗長コピー修復・スナップショットを統合する。ext4はfs-verity等のファイル内容保護を提供する。XFSにはそれらと同じ包括的内容検査を仮定できない。一方、自己記述metadata、逆参照、parent pointers、対象限定online repairは稼働中の診断・保守に適合する。内容はNiaカタログ・独立バックアップ・アプリケーション検証が負担する。fs-verity欠如をonline repairが埋めると解釈しない。

## 影響

Linux 7以上でも、CONFIG、xfsprogs、FSの逆参照機能、rescue、動作資格を別々に確認する。調査時のForkyはkernel 7.1.12-1に対しxfsprogs 6.19.0-1で、upstream 7.0からのhealerをその配布ファイル一覧で確認できない。供給差分は専用JSONに記録する。同じ供給元の対応成果物を待つか、限定的に別途審査した再ビルドを扱う必要があり、repo混在で隠さない。

上流healerは実験的である。監視モードを既定とし、正確な組と復旧が資格化されたセッションだけに修復を認可する。旧profile/layoutの解釈を黙って変えず、両schemaをv2へ更新する。既存の署名・受入lockを再発行しなければならない。
