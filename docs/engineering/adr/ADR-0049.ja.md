# ADR-0049: 実行境界・残余記録・検査ゲートの合成

状態: proposed-for-review。2026-09-07。独立レビュー・実機資格化・形式証明は未完。

## 背景

最終コードレビューで、leader終了後のhelper group残留、ログ上限直前のintent受入、mtime復元で隠れ得る観測変更、欠落lockの再作成、catalog世代とcluster世代の混同を確認した。個別の停止／設定／solver SDKを所有者が正しく合成しない場合にも、強い検査を一部落とす可能性があった。

## 決定

leaderの寿命をpidfdで観測し回収前にgroup cleanupする。新規intentは既存と新規の完了記録予算を含めて受け入れる。ctimeと開いたFD・最終パスを照合する。既存状態のlock作成は明示初期化と分離する。CASも空の私有領域のInitializeに限定し、Openでpins等を再作成しない。catalog/model世代とmembership epochは別の責任で検査する。`Pkg_Managed_Engine`で全ゲートを必須callbackとして合成する。

## 代替案と制約

終了したPIDへ後からkillする方式はPID再利用を考慮しないため採用しない。process group cleanupはcgroup隔離の代替ではない。無条件ログ圧縮や欠落lockの自動作成は、完了・再送・writer所有権の証拠を失うため採用しない。ファイルの時刻情報は排他や認証済みhashの代替にしない。すべてのcallbackを常にallowする既定実装は提供しない。

## 影響

### 互換性

MC_FS.Entry_Infoの観測フィールドとshared sourceが変わるため契約profileを更新する。旧profileで発行した要求・証拠を黙って受け入れない。管理器の実装profileも更新する。journal on-disk形式は変えず、旧recordの解析を保持する。新しいadmission制限は満杯に近い旧台帳を新規変更へ使用する許可にはならない。
