# ADR-0052 明示的な同意、native UIと資源失効の分離

状態: proposed-for-review。独立承認は未実施。

## 背景
Capsuleには方針と局所broker述語があるが、アプリ要求→利用者UI→正確な資源の受け渡し→実際の失効をつなぐ契約が不足していた。新しい権限をアクセス違反から推測すること、UI応答をbearer grantにすることは誤った権限拡大につながる。

## 決定
明示的な私有要求channel、型付き同意状態機械、既存Access backendコネクタ、独立anchor付き保存SDKをcapsulecore内へ追加する。native portalが自身で資源を生成する経路は、UI前にpossible-effect intentを永続化する。UI専用経路は承認と実効果を別状態にする。取消/期限切れと遮断完了を区別する。コードベースを増やさずNiaの単一管理正本を維持する。

## 代替案
汎用EACCES/seccomp trappingによる自動権限付与、任意のzenity通知を許可証にする方式、polkit認証をアプリ同意の代替にする方式、Flatpak installed-stateの追加、UIから直接mount/LSM変更、無UI時の常時許可は採用しない。標準のホストRegistryはsandboxの認証経路ではない。

## 影響
資源別brokerと適格なsession/launcher識別の接続が必要。backend ownerをUIDだけで信頼しない。一般アプリの内部syscallは自動的にportalへ変換されない。権限失効は既に読んだデータを回収しない。制限付きのleaseと別途の再起動計画を使う。生のdevice/ns変更を実行中のsandboxへ足さない。

## 検証と残る条件
SPARKの遷移/codec/後条件、Ada native境界と永続化試験、private D-Busでの不正応答・owner変更・timeout、SCM_CREDENTIALS/追加FD/過長入力、実desktopでのfocus・session切替・lock・多重要求、grant生存中のbroker停止を検査する。現在はPython参照とprivate native通信の試験のみ。全体daemon、実native portal、独立anchor、実kernel sandbox、Ada proofは未完または未検証。
