# ADR-0054 開発時の証明ツールの資源制限

状態: proposed-for-review。独立承認は未実施。

## 背景

2026-09-08、複数コンポーネントのGNATproveを同時に実行し、GNATwhy3の前処理で約5.6 GBのRSSを観測した。RAMとswapの余裕がなくなり、利用者からPCのフリーズと強制再起動が報告された。GNATproveのソルバー用memlimitでは前処理を制限できなかった。途中ログを保存し、完了レポートのない実行は中断として記録する。

## 決定

全コンポーネントのflow/proveは独立repo内の`ci/proof-guard.py`を通す。assuranceを正本とし、共通Make定義とともに生成工具で配る。証明は`-j1`に固定し、同一UID・同じ`/tmp`内のロックで同時起動を拒否する。通常ビルドの既定並列数も1とする。

GNATwhy3を含む子孫へRLIMIT_ASのhard limit 1536 MiB、core dump禁止、CPU時間上限、nice値の引下げを継承する。全体の実時間上限は3600秒。起動にはMemAvailable 4096 MiB以上を要求する。100 msごとに所有する実行セッションのRSSを合計し、2048 MiB超過、またはMemAvailable 2048 MiB未満で停止する。制限値は結果ログに残す。監視情報を読めない場合も失敗とする。制限到達時に自動で上限を増やしたり、制限なしで再実行したりしない。

Why3がソルバーごとに別のprocess groupを作ることを実際の全体証明で確認した。最初のgroupだけの監視・killpgでは不十分だったため、その全体実行は中断とし、監視をsession単位へ修正した。guardは既存の子を持たない専用プロセスでLinux subreaperを有効にする。終了・timeout・SIGTERM/SIGINT/SIGHUPで最初のgroupを停止し、引き取った子孫を順次停止・回収する。回収するまで自分の子として保持するため、再利用されたPIDへsignalを送らない。最初のleaderも子孫の回収終了まで保持する。外側の統合runnerは証明の終了時にSIGTERMの猶予を設ける。統合証明は最初の失敗で止まり、残るコンポーネントへ進まない。

## 代替案

ソルバーだけのmemlimit、並列数だけの削減、上限なしの自動再試行では、今回の前処理の増大を抑えられない。Distrobox内のPodmanから直接cgroupを作る方法はcontroller設定で失敗した。一方、ユーザーsystemdの一時scopeでmemory.max=3221225472、memory.swap.max=0、cpu.max=100000 100000、pids.max=128を設定し、kernelからの読戻しも確認できた。ローカルの重い検証はworkspaceの`dev/run-limited.sh`でこの制限を併用する。CIの検証コンテナも同じ総量上限を指定する。

Distrobox内の固定コンテナは一時scope内でPodmanを実行し、コンテナ内部からも同じ4値を読み戻した。この経路でのPodmanのcgroup作成無効化は、外側のkernel制限を維持したまま追加の子cgroupを作らない指定であり、制限なしの再試行ではない。再起動前のPodman実行情報は削除せず、専用の新しいrunroot/tmpdirとtransient storeを使用する。

## 影響

従来通った大きな証明でも制限内では失敗しうる。これは未完了として扱い、補助関数の契約や証明単位を見直す。条件を弱めて成功としない。CIも同じ既定値を使用する。各repoは兄弟repoなしでguardを実行できる。

RSS監視はsample間の急増を防ぐhard limitではなく、共有pageの二重加算もありうる。RLIMIT_ASはプロセスごとの仮想アドレス空間上限で、全子孫の総量上限ではない。niceはCPU quotaではない。別UID・別の`/tmp`名前空間・guardを通さない呼出しはロックの対象外。sessionを離脱するプログラム、SIGKILLによるguard自身の強制終了、他アプリによる圧迫まで封じ込めるsandboxではない。

## 検証と残る条件

小さい人工プロセスで、子孫へのhard limit継承、過大割当の拒否、二重起動拒否、低メモリ時の起動拒否、別process groupの合計RSS超過停止、複数世代の別groupの停止・回収、既存の無関係な子を持つプロセスでの起動拒否、timeoutとsignal時の子孫停止、外側runnerからの終了を検査する。試験ではホストのメモリを枯渇させない。これらは開発工具のLinux試験であり、Adaの形式証明ではない。全7コンポーネントの現行ソースの完全証明と、cgroupによる実環境での追加制限は別に検証する。
