# ADR-0059 トリガー再発火と待機解除の参照状態

状態: proposed-for-review。独立承認と製品受入は未実施。

## 背景

一つの配送batchを集約するだけでは、handler処理中に追加された同名のトリガーを
元の処理の完了で消してしまう。受信者が別の受信者を待つ場合にも、単にhandlerが
終了しただけでは待機者を解除できない。

## 決定

[参照状態](../../../../distribution/native/trigger-state.ja.md)に未処理・凍結した処理中batch・
パッケージ間の待機を分離して保持する。処理中の再発火は新しい未処理項目となる。
scopeと開始revisionに束縛したattemptを使い、古い成功応答を拒否する。
受信者が追加処理も他への待機も持たなくなった時だけ、上流の待機解除を伝播する。
循環待機と結果不明は保持する。

## 代替案

処理開始時に待機を消す方法、handler終了だけで全待機者を解放する方法、
復号時に自動再実行する方法、Pythonの第二の導入済みDBは採用しない。

## 影響

原本の発火先計算と接続する純粋な参照モデルを追加する。
検査対象の状態のcodecは既存CAS/WALへ束縛するための入力であり、単独の認証機構ではない。
成功観測の参照遷移を本番認可・成功検証として公開しない。
Ada/SPARKと固定vendorには変更を加えない。稼働PMがこれで完成したとは扱わない。

## 検証と残る条件

旧新版の発火、同名の再発火、noawait追加、別の受信者への待機、待機の連鎖・循環、
処理中checkpointの再読、古いattempt、内容・scope不一致と資源上限を検査する。
モデルはhandlerを実行しない。package lifecycle全体と失敗状態、削除、interest寿命、
native再検査、実行器の観測認証、CAS/WALと電源断の受入は未完である。
