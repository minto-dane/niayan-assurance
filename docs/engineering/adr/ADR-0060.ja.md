# ADR-0060 元DEBのnative envelope検査とCAS保存

状態: proposed-for-review。独立承認と製品受入は未実施。

## 背景

Pythonの元DEB解析結果だけではnative実行器が元データと内部位置を独立に確認できない。
圧縮アーカイブを外部工具で展開してから信用すると、原本との対応や拡張部分を失いやすい。

## 決定

pkgcoreへ[元DEB読取SDK](../../../../distribution/native/deb-container.ja.md)を追加する。
既存CASの元DEBを開き、ar headerと順序、数値、サイズ、paddingを有界に検査する。
検査中の全バイト列と各メンバーをhashへ束縛する。呼出側が与えるenvelopeは保存時に
原本から再計算した全項目と照合する。圧縮済みの正確なメンバーを同じCASへ保存する。
対応可能なminor版と無視可能な拡張も原本とhashで保持し、隠れて削除しない。

## 代替案

Pythonを第二の特権導入器にする方法、位置情報を無検査で使う方法、ar検査だけで
tar・依存・署名・効果まで有効とする方法、元DEBの再梱包は採用しない。

## 影響

公開CLIや稼働DBを増やさない。UID 0は拒否する。MC_Storeの上限8 GiB、
制御メンバー16 MiB、arメンバー16個、64 KiBのI/Oバッファを使う。
期限は協調的であり、CAS初期hashと同期I/Oを中断する外側の時間・資源制限も必要となる。
SPARK_Mode=>Offのruntimeであり、既存の数理入力と固定vendorは変更しない。

## 検証と残る条件

人工envelopeの切断全位置、不正header、位置偽装、CAS破損、期限切れ、root拒否を検査する。
保存済み実DEBは独立したar工具の出力と照合し、原本を維持したことを確認する。
圧縮tarの検証・展開、control意味、署名信頼、全効果、既存catalog/WALとの適用接続、
bootと電源断の受入は別の条件であり、このSDKで完了したとは扱わない。
