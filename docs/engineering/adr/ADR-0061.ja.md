# ADR-0061 圧縮制御アーカイブのnative読取と保持

状態: proposed-for-review。独立承認と製品受入は未実施。

## 背景

元DEBのar検査だけでは制御ファイルの内容を得られない。試験ではlibarchiveのtar読取りが
CRCの壊れたgzipを受理した。tarのEOFだけで圧縮stream全体の整合性を認めてはならない。

## 決定

[制御読取SDK](../../../../distribution/native/deb-control.ja.md)で、元envelopeを再検査して
制御メンバーを保存する。薄いC境界から未改変のzlib/liblzma/libzstdを呼び、streamの終端と
全入力消費、展開量、時間を検査する。圧縮を検査した後のメモリをlibarchiveのtar読取へ渡す。
全通常制御ファイルを原本のbyte列のまま同じCASへ保持し、内容と属性を元DEBへ束縛する。
失敗時に部分inventoryを返さず、スクリプトを実行しない。C境界もcanonicalソース索引へ載せる。

## 代替案

CRC不正の試験を削除する方法、libarchiveに外部解凍programを自動起動させる方法、
上流codecへの独自patch、Pythonの第二の特権writer、未知の制御効果を正常扱いする方法は採用しない。

## 影響

pkgcoreは小さなC codec境界を含む。直接の開発依存を明記し、Adaと同じ警告・hardening・
パス再現性方針でビルドする。共有CIの固定環境へ直接依存を宣言する。
SPARK証明対象の数学的srcとvendorには変更しない。UID 0のSDK呼出しは拒否する。

## 検証と残る条件

合成した圧縮破損、末尾・連結stream、危険な制御名・型・属性、個数・展開量を検査する。
元DEBと制御内容を別のar/Python tar読取とCAS readbackで照合する。
小さなC境界とAdaの接続はSPARKの対象外で、実行検査と独立レビューが必要である。
全tar形式、制御field意味、保守scriptの効果変換、data.tar、catalogと稼働writer、
実root/boot切替と電源断は別の未完条件として維持する。
