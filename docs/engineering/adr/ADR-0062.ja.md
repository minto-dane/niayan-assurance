# ADR-0062 原本制御項目とnative識別情報の検査

状態: proposed-for-review。独立承認と製品受入は未実施。

## 背景

元の制御ファイルをCASへ保持しても、native側で名前・版・Source・保護属性を解釈しなければ
導入計画の入力にならない。一般的なtext parserやfield位置の無検査な受渡しでは、
重複・折返し・文字コードの相違で異なるpackageを認める可能性がある。

## 決定

[制御項目の読取](../../../../distribution/native/deb-metadata.ja.md)を追加する。
単一stanza、UTF-8、field名と空値を検査し、privateな位置索引を全raw hashへ束縛する。
単純値・folded・multiline・rawを明確に区別し、未知項目も取り出せるようにする。
元DEBのar、圧縮control、raw controlを再検査して識別情報まで接続する。
source identityと保護属性は明示的に解釈し、全依存・効果の成功判定には使わない。

## 代替案

外部のpackage managerへ意味解釈を委譲する方法、未知項目を削る方法、
値を固定bufferへ切り詰める方法、raw hashだけを比較して外部の改変可能な位置を信用する方法は採用しない。

## 影響

大きな中間inventoryと観測recordは必要な段階だけheapに確保し、すべての終了経路で解放する。
通し試験でstack不足を検出したため、制限を増やさず配置を修正した。
新runtimeはSPARK証明対象外。固定vendorと数理srcは変更しない。
本番接続仕様に残っていた旧ベース版・旧公開CLIの表記を現行のDebian 13と採用CLIへ合わせる。

## 検証と残る条件

文字・名前・値・行/項目数の境界、必須項目と属性、原本の取り違え、折返し、元DEBの通し経路を検査する。
実原本の識別情報はDebianのread-only工具と比較する。これはビルド時の独立oracleであり、稼働backendではない。
依存関係の完全なnative解釈、phase、全任意fieldの意味、全DEB効果、所有権・catalog、
認可・boot・完全置換ISOは引き続き未完である。
