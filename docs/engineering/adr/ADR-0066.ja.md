# ADR-0066 世代イメージ生成器の属性受入

状態: proposed-for-review。製品用backendの採用ではない。

## 背景

原本payloadの全属性は既存世代v1で表現できない。制御状態用のファイル操作を
一律に緩めず、未改変の上流工具でroot imageを構築する代案を調査した。
固定Debian 13のerofs-utils 1.8.6-1へtarを直接入力する試験では、
終了値、fsck成功、二回のimage一致だけでは原本の意味を保証できなかった。

## 決定

当該版のtar直接入力をNiaの世代生成器として採用しない。
ACL欠落、前方hardlinkの構築失敗、GNU負時刻の拒否、PAX小数時刻の不一致を
原本と独立したimage読戻しで記録した。原本を削ったり上流をpatchして適合させない。
これは当該入力経路の判断であり、EROFSの全利用形態を否定する判断ではない。

今後の生成器も、元情報と生成物の意味の照合を必須とする。
原本に記録された時刻・名前と稼働filesystemが実現する属性を区別し、
実現できない属性は明示的な製品契約がない限り黙って削らない。
暗黙の親directoryには明示的な世代policyと所有権が必要である。
生成失敗時の出力は公開対象にせず、論理サイズ・割当量を検査してから保存する。

## 代替案

旧ファイルプランへの属性切捨て、全ownerのroot化、時刻の一括上書き、
成功終了値だけの受入は採用しない。独立した隔離root実行器、版付き属性契約と
所有権管理の拡張は引き続き必要であり、この実験では実装・認定していない。

## 影響

既存runtime、共有contract、SPARK入力、稼働管理器、ISOの変更はない。
実験のreaderは限定された合成入力の読戻し用で、製品のimage検証器ではない。
失敗出力は巨大な疎ファイルを残したため、証跡にはログとstat情報を保持する。

## 検証と残る条件

[17 imageの検証記録](../../../../distribution/evidence/native-transition/generation-image-01/README.ja.md)と
[境界](../../../../distribution/native/generation-image.ja.md)を参照。
基本USTARの権限・所有権・hardlink・特殊inodeと内容は照合できた。
4組のimage bytesも一致したが、採用profile全体の属性一致ではない。
kernel mount、boot、全元DEB、実電源断、writer認可、mutable dataと全効果の接続は未完。
