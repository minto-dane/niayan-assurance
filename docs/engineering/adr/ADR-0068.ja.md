# ADR-0068 選択原本・control意味・payload索引の完全一致

状態: proposed-for-review。稼働catalogと導入認可の受入は未実施。

## 背景

原本のcontrolを正しく読めても、ファイル索引が別の集合なら選択したpackageを
構成できない。package数の一致だけでは別原本への置換や空payload packageの欠落を
検出できない。公開Observationをそのまま信用すると原本にないidentityを渡せてしまう。

## 決定

[選択候補catalog](../../../../distribution/native/selected-catalog.ja.md)を追加する。
元DEBを既存native readerで再観測し、compactなidentityと全11関係項目を保持する。
Sealは明示した選択原本・期待するraw control hash・観測した原本・sealed payload
索引の原本集合を完全照合する。同じ原本または同じname/architectureを二重登録できない。
全体成功まで読取を隠し、失敗は全candidateを破棄する。再Sealでも入力を再照合する。

原本digest順のfingerprintへpayload索引hashとcontrol archive/raw control hashを束縛する。
依存の代替候補・group・version・architectureを保持し、Provides等を独自の簡易意味へ変換しない。
同名の異architectureは情報として保持するが、共存可能と認定しない。

## 影響

4096原本・262144 atom・text合計64MiBまでのprivate memoryで扱う。
各packageへ巨大なDocument/Expressionを固定保持せず、有界な共用一時領域からcompact
vectorへコピーする。SDKのCAS原本保存以外に永続状態を書かない。

## 代替案

Pythonの第二の導入済みDB、原本リストの暗黙dedup、metadata hashの
省略、最後の版を採用する方法は使わない。

## 検証と残る条件

集合順反転、欠落・混入・control不一致・同一identityの再梱包/別版、期限、UID0と
原本inventory破棄を試験する。原本を上流ar/codecsとPython tarfileで読み、identity・全atomと
canonical hashを独立照合する。固定ビルド・独立再現性・対象入力の資源を測る。

選択リスト自体は認可でなく呼出側の主張である。resolver結果と認証済み媒体・policyを
結ぶguard、最終集合の関係成立とMulti-Arch、実行phase、実効owner、全効果、CAS pin閉包、
世代実行とbootは引き続き必要。新runtimeはSPARK証明の対象外。
