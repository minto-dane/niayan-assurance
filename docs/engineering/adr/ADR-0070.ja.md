# ADR-0070 既存世代の変更集合と保護対象の保持

状態: proposed-for-review。通常更新の読取SDK。稼働管理器は未接続。

## 背景

候補の最終集合が成立しても、前世代に存在した保護対象の消失は検出できない。
変更集合を原本と前後catalogへ束縛し、後続のphase・所有権検査へ渡す必要がある。

## 決定

[native変更集合](../../../../distribution/native/transition-plan.ja.md)は二つのsealed
catalogを受け、正確なpackage name/architectureごとに原本を比較する。
追加・削除・更新・降格・同等版の再梱包を区別し、targetの最終集合検査を内包する。
前世代のEssential/Protected identityとflagの消失は通常更新で拒否する。
保護移行には別の検証済み移行契約が必要であり、このAPIはforce入力を持たない。

## 代替案

最終集合検査だけで前世代の保護も検査済みとする案、Provides/Replacesをidentityの
保持とみなす案、callerの真偽値だけで保護移行を許す案は採用しない。
保護flagの維持はNiaの通常更新policyであり、上流の版更新全般との同一動作を主張しない。

## 影響

既存の非空catalog契約を維持し、空世代からのbootstrapを暗黙に導入しない。
壊れた前世代からの修復は許すため、前世代の最終集合成立を前提にしない。
最大8192変更をcompactに所有し、期限とUID0拒否を維持する。入力の破棄後も計画は不変。
公開前に前後catalog・target receipt・rule versionと変更全件をhashで結ぶ。

## 検証と残る条件

36合成原本・44ケースで保護flag全組合せ、削除、architecture変更、代替名、版比較、
再梱包、接頭辞順序、入力の順序/寿命、依存破壊、修復、途中失敗、期限を検査する。
独立した原本読取器でdeltaとhashを照合し、通常CIへ組み込む。
固定ビルド・再現性・root拒否・sanitizerの結果はsourceに束縛して別証跡へ記録する。
認証済み前世代とのguard下照合、保護移行、bootstrap、rollback floor、phase・所有権・
効果・CAS保持・実root/bootは未完。新runtimeはSPARK対象外である。
