# ADR-0071 正規catalogのCAS保存と再観測

状態: proposed-for-review。永続candidateのSDK。稼働世代の認可は未接続。

## 背景

世代manifestはcatalogのCASオブジェクトを要求するが、selected catalogは従来
fingerprintだけを計算していた。実際の保存byte列と、元DEBから再構築する経路が必要である。

## 決定

[catalog保存SDK](../../../../distribution/native/catalog-store.ja.md)は既存NIACSEL1の
hash対象byte列をそのままCASへ保存する。公開型やhash形式を変更せず、別IDと第二の導入済みDBを作らない。
読取では形式・順序・全digestを検査し、全元DEBのcontrolとpayloadをnative readerで再観測する。
完全照合時だけcatalogとpayloadを返し、失敗時は旧成功を含め両方を消す。

## 代替案

メタデータcacheを原本の代替にする案、原本欠落を空packageとして扱う案、
新しい導入済みDBやgeneration.nextの直接参照を正本にする案は採用しない。
認証や排他予約を省略した「現在のcatalog」getterにはしない。

## 影響

最大4096原本で正規frameは最大393272 byte。保存は既存CAS writerへchunkで渡す。
読取bufferはheap上の上限付きで、原本の処理は既存bounded readerへ委ねる。
UID0拒否・期限・外側資源制限を維持する。完全だが未参照のCASオブジェクトが失敗後に残る場合がある。

## 検証と残る条件

4合成原本の全identity・11関係項目・全claimを保存前後で比較し、独立したar/tar読取器で
payload index、catalog frameとhash、表示された全metadataを照合する。
20形式不正、原本/catalog欠落、期限、再open、UID0、旧成功出力の消去も検査する。
固定build・全回帰・再現性・sanitizerの結果はsourceへ束縛する。新runtimeはSPARK対象外。
供給認証、accepted generationとの同一reservation下照合、CAS保持閉包、phase/効果/所有権と
実root/bootは未完。保存成功そのものはインストールや現在世代の認可ではない。
