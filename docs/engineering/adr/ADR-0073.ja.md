# ADR-0073 Native catalog由来の正規保持閉包

状態: proposed-for-review。catalogの物質化された参照集合。全世代GCではない。

## 背景

catalog原本をCASへ保存し現世代と結び付けても、既存pinは参照先一覧を解釈しない。
元DEBや派生内容の保持を明示しなければ、保持一覧の省略や欠落が復旧時まで見えない。

## 決定

[保持閉包の仕様](../../../../distribution/native/catalog-retention.ja.md)に従い、
元DEBから全参照先を再観測し、既存CASに正規一覧を保存する。
PrepareとVerifyを区別する。Verifyは全掲載objectを先にhash検査し、その後に正確な集合を
再計算して比較する。pinは既存immutable namespaceを使い、別用途のidentityを上書きしない。

## 代替案

CASディレクトリ全体を保持対象とする、掲載されたhashの存在だけを検査する、
Verify中に欠落を自動再生成して成功とする、第二の導入済みDBで保持状態を管理する方法は採用しない。
原本だけでも再構成は可能だが、現在のnative readerが物質化する内容と属性も明示して保持する。

## 影響

新規runtimeのみで共有contract・旧永続形式・proof入力を変更しない。
同じstore予約を保持し、UID0拒否と期限・外側資源制限を維持する。
任意scriptの実行・ファイル展開・object/pinの削除・accepted stateの更新はない。

## 検証と残る条件

二catalog、五合成原本、control全内容と七payload種の一覧を独立readerで比較する。
省略・余剰・順序・重複・形式不正、全memberの単独欠落、破損byte、pin再試行/衝突と期限を試験する。
最大容量・全OS原本、世代/効果/認証/復旧の全root、保持期間・安全なGC・本番admissionは未受入。

全workspace検査で、既存の世代公開driverが相対媒体pathをそのままabsolute-onlyのFS SDKへ渡す問題を検出した。
driver内でFull_Nameに変換し、絶対pathを渡す単独CIと相対pathを渡す全体runnerの両方を検査する。
