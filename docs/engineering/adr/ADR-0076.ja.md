# ADR-0076 公開計画へ束縛したnative検査記録

状態: proposed-for-review。本番adapterと実root/bootは未認定。

## 背景

現在世代から更新計画を観測できても、その結果を公開計画へ束縛しなければ、公開時の
認可対象と検査したpolicy/candidateが一致するとは限らない。

## 決定

[公開検査記録](../../../../distribution/native/publication-intent.ja.md)に従い、
元DEBからの検査記録NIAGINT1をCASへ保存し、NIAGEN03の必須参照とする。
物理計画→descriptor→manifest→検査記録というhash参照で既存Managed認可へ結び付ける。
Publisherは実際の基準を予約下で照合し、記録のpolicyによるnative検査を実行前に再計算する。
初期構築と通常更新を分離し、既存の保護維持規則を弱めない。

## 代替案

公開時に別引数で未束縛のpolicyを渡す、第二の承認DBを追加する、構造検査だけで
native検査の代わりとする方式は採用しない。既存のread APIを保持中の同じlockへ再入させない。

## 影響

NIAGEN01/02のheaderとtransaction hashを維持し、NIAGEN03を追加する。
新しいPublishは新版のみを認める。旧版の途中状態は保持した旧実装による復旧を先に完了する必要がある。
新しい公開CLI、権限override、常時成功callback、別writerを追加しない。
CAS予約の既存の受け渡しと、Managed guard・stage予約を維持する。

## 検証と残る条件

版ごとの正規形式、記録を含む保持欠落、二世代公開・復旧、独立した結果hashの計算を検査する。
構造上は正しく組み立てられた候補も、不正なnative結果・root・基準では公開前に止める。
全DEB phase・所有権・効果・属性、本番供給/policy adapter、旧版移行と実起動の受入は未完である。
