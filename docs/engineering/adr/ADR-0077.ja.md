# ADR-0077 明示的なDebian 13原本pinと共通TUF供給認証

状態: proposed-for-review。本番の独立trust floorとmanaged adapterは未認定。

## 背景

旧原本認証器はForky・amd64とValid-Untilの存在を固定していた。
Trixie本体のReleaseはValid-Untilを持たず、securityのcomponent宣言にはupdates/接頭辞がある。
また、Releaseに列挙される未使用Contentsのサイズを索引読取上限と誤って同一視していた。
このまま署名済み供給policyを接続しても、Debian 13の原本認証として動作しない。

## 決定

[原本供給仕様](../../../../distribution/native/archive-supply.ja.md)のv2 policyで、
正確なcodename、suite、index architecture、components、InRelease hash、日付floor、期限を指定する。
署名済みpolicyに現在時刻を埋め込まず、独立に観測した時刻をAPIへ渡す。
Trixie本体の期限欠如には有限のローカル期限を要求し、期限付き上流metadataを延命しない。
実際に読むindexの容量は従来どおり制限し、無関係な大きいContentsは読み込まない。

既存TUF Repositoryのtargetとしてpolicyを認証し、既存gpgvとDEB読取器で
InRelease、Packages、元DEBとcontrolの一致を検査する。第二のtrust cacheや鍵、writerは作らない。
旧v1は比較工具用に維持し、共通native供給の入口では拒否する。

返却前に唯一のcheckpointを新しい上流Updaterへ渡して、保持原本を現在時刻で再検証する。
署名済みmetadataの探索で使用したroleと全top-level roleの最短期限を観測期限へ反映する。
checkpoint hash・repository identity・予約を前後で照合する。取得器は保持metadataだけを返し、
追加ネットワーク取得、第二の永続cache、初期rootへの復帰を行わない。

## 代替案

単純なcodename置換、署名/期限検査の無効化、ミラーからの鍵採用、全索引の容量枠引上げを採用しない。

## 影響

新規公開CLIは追加しない。architectureの明示指定は読取範囲であり、実OSのarchitecture認定ではない。
TUF session内の再読取を最新のremote policy取得と同一視しない。
供給結果のhashをnative CAS・現在世代・公開計画へ同じ予約で束縛する本番adapter、
全phase/効果/所有権、独立trust floorと実起動は引き続き未完である。

## 検証と残る条件

実OpenPGP/TUF署名、原本DEB、期限とpolicy不一致の拒否を試験する。
処理中の各roleの期限到達、未使用/使用した委譲role、鍵交代後のroot、保持checkpointや
予約の変更、オフライン性、sessionと要求枠も実署名fixtureで検査する。
公式のTrixie本体/updates/security metadata、元binaryと対応ソースも別に照合する。
数学的入力とAda runtimeには変更がなく、既存の形式証明を重複実行しない。
