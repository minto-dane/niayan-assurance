# ADR-0079: 新規原本の供給記録集合を正確な更新contextへ束縛する

状態: proposed-for-review

## 背景

原本単位のNIASUP01だけでは、更新で必要な原本の認証が漏れていないことを示せない。
一方、変更しない導入済み原本に新しいmirror掲載を要求すると、正当な削除や保守を妨げる。

## 決定

元DEB hashによる候補−基準の正確な差集合を使い、root、基準descriptor/closure、
候補catalog/closureへ束縛するNIASMAP1を既存CASに保存する。

全参照欠損を再生成前に検出し、独立authorityと生の原本から検査する。
新規導入のfresh verificationと、過去記録のhistorical retentionを別APIとし、保持の成功を認可にしない。
全APIのI/Oを含む期限を守り、準備後のCAS書込みが期限を超えた場合も成功addressを返さない。

## 代替案

候補全体への一律再取得、package名/versionだけの比較、供給記録の件数だけの一致は採用しない。
保持検査だけで期限や独立鍵の認証を省略することも採用しない。

## 影響

原本差集合を線形時間で比較でき、余分な原本や別の基準へ同じmapを流用できない。
map自体はroot.stateを読む権限やacceptedな系譜を証明しない。基準descriptorの実受理を
publication予約下で証明し、mapを認可対象計画とtyped retentionへ結ぶ接続が必要である。
新規admissionと既存transactionの復旧で供給期限をどう扱うかは、記録済み認可と一体で実装する。
新形式のmanifestや期限切れ復旧の既定許可を先に追加しない。

## 検証と残る条件

テストは実native catalog、合成observer、多原本の差分、欠損、期限、root/context変更を含む。
独立bridgeは実TUF/OpenPGP発行からmap preimageまでを照合する。
実root/boot、全DEB効果、鍵配備、全世代GCを完成扱いにしない。

仕様: [供給記録集合](../../../../distribution/native/supply-map.ja.md)。

## 実装上の共有参照検査

2026-09-10。前段検査と構造保持では、呼出し内の有界なhash集合を用い、全receiptが必要とする
原本を重複せずrehashする。全集合の確認前にはnative再構築を開始しない。呼出しをまたぐcache、
検査を省略する公開API、永続形式の変更は追加しない。個別の署名・原本検査は維持する。
複数行・複数役割の共有と、前回成功後の原本欠損を回帰試験で確認する。
