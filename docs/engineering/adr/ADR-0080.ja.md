# ADR-0080: 供給観測を公開計画へ保持し、新規admissionと記録済み復旧を区別する

状態: proposed-for-review

## 背景

原本差集合だけでは実基準への束縛がなく、短い供給期限を全ての復旧へ適用すると認可済み更新まで停止する。
過去時刻や鍵を自己申告する復旧は、新規更新の認証を省略する入口になり得る。

## 決定

NIASPOL1に差集合map、観測秒、独立authority集合を正規化して保持し、NIAGEN04から参照する。
新規Publishは独立した現在policyと全フィールドを照合し、保持観測から現在までの有効性をnativeで再検査する。
記録済み扱いは実root.stateと完全なpin/journal監査を通過した正確なplanだけに許し、署名・原本を
保持観測時刻で再検査する。現在の鍵/floor/age照合と全Managed guardは復旧でも必須である。
StageからEngineへroot/CAS予約を受け渡した後は、Engine.Check_Inputsを通じて保持中の実予約下で
root.stateと全native入力を再検査する。先行した観測結果だけを持ち越して開始しない。

## 代替案

毎回新しいmirror掲載を要求すること、保持検査だけの復旧、自己申告鍵/時刻、別の導入済みDBや
未束縛のadmission sidecarは採用しない。旧manifestへ余剰bytesを足して新形式として扱わない。

## 影響

manifestが既存pinからpolicy/mapを保持し、物理計画がそれらを認証対象へ含める。
file-WAL/root.stateの形式は変えず、Preparedだけの孤児は新規admissionとして検査する。
旧v1/v2/v3のPublish/replayは明示的に拒否し、移行前復旧には旧実装が必要である。
回復中も現在policyの完全一致を要求するため、鍵移行・floor引上げには別の認可済み回復方針が必要である。

## 検証と残る条件

保持policyの全byte変更、境界・非1添字、独立鍵/floor/時刻変更、期限切れ新規更新拒否、
認可済み更新の期限切れ後の復旧、manifest/policy/map/原本欠損、実際の公開保存への故障注入を検査する。
本番adapter、rollback耐性、全DEB効果、実root/bootとGCを完成扱いしない。
