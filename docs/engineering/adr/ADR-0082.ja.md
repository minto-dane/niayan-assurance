# ADR-0082: rootアーカイブと世代公開計画の一体保持

## 背景

NIAROOT1による元DEB rootアーカイブは組み立てられるが、世代pinと認可対象の公開計画に
参照がなければ、採用claimと実tarが公開・復旧の必須根拠にならない。

## 決定

NIAGEN05を追加し、既存の供給policy/intentに加えてNIAROOT1 hashを保持する。
一つのbatchでcatalog、tree、tree/root.tarを格納する。保持検査はenclosing catalog/closureと
root manifestを一致させ、実tarの再検証結果を格納planの内容hashへ照合する。

## 代替案

未束縛のsidecar、別のinstalled DB、独立したroot選択の認可入口は作らない。
旧manifestの予約bytesを再解釈しない。root内属性を旧file-planの属性集合へ落とさない。

## 影響

世代pin、descriptor、既存の物理公開計画とcomposed guardを使用する。
旧v1〜v4のbytesとtransaction導出は保持する。v5のtagとheader長を明示し、
v4は内部制御状態の従来profileとして残す。root deploymentの本番providerにはv5を要求する。
stagingしたtarの存在を展開・boot成功として扱わない。既存の非特権境界は維持する。

## 検証と残る条件

元span、物理staging、世代pin、enclosing targetと格納hash、旧形式への偽装、
公開前・記録済み復旧・現在世代での実参照欠損を検査する。独立読取器で実accepted stateから
tarまで辿る。影響する旧stage/公開経路も検査する。本番認可/供給provider、typed GC、
特権展開、全DEB効果、実root/bootと完全置換ISOは未完として維持する。
