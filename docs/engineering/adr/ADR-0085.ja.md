# ADR-0085: 実予約FDと永続intentで非公開root準備を接続する

## 背景

独立workerの成功だけでは、callerのCAS予約維持やサービス停止後の結果識別を満たさない。
非特権SDKのUID0拒否を解除せず、非公開の準備権だけを分離する必要がある。

## 決定

内部coreの実peer UIDをUnix seqpacketで確認し、tarと同じopen file descriptionの実CAS予約を
SCM_RIGHTSで受け渡す。固定した予約inodeを検査し、workerまで保持して解錠しない。
root所有の保護された永続bankへintentをfsyncしてから展開し、結果を排他的に保存する。
起動時に欠損した状態を初期化しない。再起動後の履歴を物理再検証や公開認可にしない。

## 代替案

一般利用者のUIDやJSON上の自己申告、lock名だけの照合、受け渡したflockの明示解除、
先に展開して後からintentを作る方式、欠損状態の自動初期化は採用しない。

## 影響

公開コマンド・既存catalog/wire・導入済み状態の正本は変更しない。
準備専用のsocket activation入口と保護policyを用意する。製品unitとaccount配備は別工程。

## 検証と残る条件

使い捨てVMでpeer/FD/実worker、予約維持、別予約/重複拒否、再起動とサービス停止を確認する。
試験の変更境界に絞り、入力不変の証明・全suite・性能campaignを繰り返さない。

世代admissionの本番adapter、供給とsite効果、容量予約、再検証/回収、boot、完全置換ISOは未完。
専用coreの準備権はnative planの認可そのものではない。SIGKILLは物理電断の代用ではない。
