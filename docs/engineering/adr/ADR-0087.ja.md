# ADR-0087: 内部root準備のaccount・mount・serviceを配布物として管理する

## 背景

fixture内の任意launcherだけでは、稼働時のaccount、初期化、権限、停止と更新の契約が定まらない。

## 決定

Debian標準のdebhelper/sysusers/systemdによる独立ソースパッケージを用意する。
非rootのcore accountは名前で束縛し、root設定で実UIDへ解決する。bankとCASの初期化は
明示的installer工程とし、通常起動・インストール・更新時の自動再初期化を行わない。
実サービスはsocket activation、既存mount、限定capability、資源上限とgroup全体の停止を使う。

## 代替案

UID固定、rootでnative SDKを実行する方式、一般利用者へのsocket公開、lockの自動再作成、
package更新時の自動有効化は採用しない。上流daemonやsystemdへ独自patchを加えない。
PrivateDevicesによるCAP_MKNOD喪失と、API mountで隠蔽が無効になる/dev tmpfs指定を避け、
配布した専用directoryと四つの必要deviceの読取専用bindを使う。

## 影響

v1設定を保持し、v2にaccount名を追加する。公開管理コマンドは増やさない。

## 検証と残る条件

二つのdirectoryから主DEBとdbgsymの再現性を確認し、使い捨てVMへ導入した実unitから
元DEB fixture→native世代→実workerを実行する。再起動後の履歴、lock/設定欠損、実mountを検査する。

製品installerによるnative CAS初期化と本番providerは未接続。fixture認可を出荷しない。
この配布物は独立認可/供給、全DEB効果、物理再検証/回収、起動切替や完全置換ISOの認定ではない。

仕様: [service配備](../../../../distribution/native/service-deployment.ja.md)。
