# ADR-0090: CAS外の保護site供給provider

## 背景

世代公開は実CAS予約を保持したままObserve_Supplyを呼ぶ。保持policyに含まれる鍵や時刻を
返すfixtureは独立供給providerではなく、callback内でCASを再予約する実装も使用できない。

## 決定

非rootのPkg_Site_Supplyがroot所有の現在policyと独立floorを毎回読み、実UTCを採取する。
全祖先の保護、正確なwire、root identity、完全policy hash、serial/時刻下限と期限を検査する。
contextを一つのroot/transaction/plan/retained policy/mapに束縛し、変更・失敗でsessionを停止する。
CASは読まず、公開側の実reservation/原本/完全policy一致と全managed guardを維持する。
内部のread-only配備確認工具をcomponent artifactへ含めるが、既定policyや本番鍵は作らない。

## 代替案

CASの自己申告、receipt内時刻、常時成功callback、rootでのcore実行、file hashだけを
署名やhardware rollback耐性として扱うことは採用しない。

## 影響

内部appと登録Ada mainが各一つ増える。共有API/vendor、世代/供給記録の永続形式は不変。
運用側がfloorを世代rollbackから分離し、正しい時刻とpolicy配備を管理する必要がある。
policy更新後の既存sessionは自動復活せず、処理の不確定性は既存journalで扱う。

## 検証と残る条件

bounded parser/拒否出力、既存publisher回帰、実VMのroot-owned policyと原子的更新を確認し、
実publisher内で複数回呼ばれてCAS再予約が不要なことと不一致拒否を検査する。
VMのmanaged認可/秘密鍵はfixture。独立レビュー、production signer/認可、全installerと
非rollback floor/正しい時刻のsite受入、全効果/boot/置換ISOは未完である。
