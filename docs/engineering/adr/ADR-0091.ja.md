# ADR-0091: 認証原本だけを署名するcredential provider

## 背景

原本receipt発行器には外部署名callbackが必要で、これまでの実接続は一時鍵のfixtureだった。
秘密鍵のargv/env渡し、rootでの検証、任意messageの署名daemonは信頼境界を広げる。

## 決定

独立scope/key/epoch/lifetimeを受ける内部credential APIを追加し、既存TUF/OpenPGP認証後だけ
32-byte seedを読む。固定domainと署名対象の範囲を再検査し、既存の署名/保持policy再検証を使う。
systemdのread-only credentialまたは完全seal済みmemfdを受け、単なるO_RDONLY fileは拒否する。
root:rootの正確なservice ACL、またはservice UID所有0400を明示的に扱い、借用FDのoffsetを保つ。
processは非root、core dump不可・非dumpableとし、API返却で保護を戻さない。

## 代替案

平文鍵のコマンド引数、任意観測の署名、自己申告の公開鍵、未認証原本からの署名は採用しない。
HSM/remote signerは既存callbackの将来providerとし、この変更でその耐性を主張しない。

## 影響

既存永続形式、共有API/vendorと管理コマンドを変更しない。Python秘密情報の完全消去は保証しない。
専用UID・短命service・swap禁止・有限期限・protected code/configはsupervisorの責務となる。
read-only mount flagは配備由来や別alias不在の証明ではない。

## 検証と残る条件

関連Python試験とnative bridge、実systemd LoadCredentialを使う使い捨てVMで確認する。
初回VMで発見したroot所有ACL形式とprivate umask下のfixture制約を実際の形式へ修正する。
fixtureのTUF transportと一時鍵を本番認可にしない。job/service packaging、独立設定の配備、
鍵運用/更新/失効、実HTTPS、publisher/controller、全managed認可と実bootは未完である。
