# ADR-0093: native CAS予約を保持する供給observer接続

## 背景

独立observerの配布物はあるが、native coreが保持原本から呼び出し、同じwriter予約のまま
結果を供給計画へ結ぶ接続がなかった。

## 決定

内部Pkg_Archive_Observerが既存の開いたStoreと独立authority/observer UIDを受け取る。
CASで再検査した原本のread FDだけを固定socketへ渡し、元の予約を開き直さず保持する。
C境界は有限BOOTTIME、正規UTF-8/JSON、kernel senderとsealed FD/hashを検査する。
Ada側は独立署名と全原本hashを確認し、同じStoreへpolicy/receiptを保存してから原本と現在時刻を再検査する。
失敗時は両出力をzeroにする。保存途中の未参照objectやTUF checkpointの進行は残り得る。

## 代替案

通信中のCAS予約解放、第二writer、保持receiptによる独立authorityの代用を採用しない。

## 影響

共有API/vendorと永続形式、公開CLIは不変。非root内部SDKを追加する。
新しいreceiptは既存の供給map/保持policyへ明示的に結び付ける。呼出側は現在site trustを再観測し、
全managed認可と世代公開の条件を満たす必要がある。

## 検証と残る条件

境界単体検証と実配布observerの使い捨てVMで、native原本から実HTTPS/TUF/OpenPGP/credential、
CAS保存、catalog/closure、供給map/保持policyまでを通す。HTTPS取得中にも予約の競合排除を観測する。
不正入力・別control/UID・service拒否で出力消去と予約保持を確認する。
fixtureの供給計画は実rootのadmissionや世代公開ではなく、全controller・installer接続は別工程である。
