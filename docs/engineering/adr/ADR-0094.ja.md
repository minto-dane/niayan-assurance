# ADR-0094: 計画段階の独立供給trustと公開への束縛

## 背景

site供給providerは完成したplan/map/policyを必須とし、これから供給計画を作るcontrollerで利用できなかった。
原本認証とmap作成にcallerの鍵・時刻を直接渡す接続も残っていた。

## 決定

site sessionに明示的な計画状態を追加する。独立policy/floorを固定し、plan/map/policyは存在しないまま
計画用に観測する。供給plannerが各原本の認証とmap/保持policy作成を同じCAS予約で行い、
各段階で現在site trustを再確認する。完成後のBind_Publicationは実際のhashへ一方向に束縛し、
元のpin・時計高水位・期限を維持する。計画用sessionを公開callbackで使うことは拒否する。

## 代替案

計画前に架空のhashを渡す方法、保持policyによる自己承認、通信中のCAS予約解放、
設定更新の途中採用、期限の自動延長は採用しない。

## 影響

内部site APIに計画状態と束縛操作を追加し、既存公開Open/Observeの契約と永続形式は維持する。
新plannerは失敗時に三出力を消し、site sessionを閉じる。未参照object/TUF checkpoint進行は残り得る。
共有API/vendor、数学的入力と公開コマンドは変更しない。

## 検証と残る条件

既存siteの境界と実observerのVMを検証する。計画/公開状態制約、HTTPS処理中のpolicy/floor変更と欠損を扱う。
実serviceから供給計画への接続が成功しても、全managed認可、実predecessorのadmission、公開コマンドと
installer、本番鍵/floor/時計、全DEB効果とbootの完成ではない。
