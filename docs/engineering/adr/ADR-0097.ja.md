# ADR-0097: 設定候補に束縛した選択と保持対象

## 背景

実localのsnapshotと三者比較だけでは、選択がどの原本・観測状態を対象にしたか、
退避先が使えるか、次回vendor baselineと必要な保持物は何かを結び付けられない。

## 決定

元DEBの宣言と通常file内容を再観測し、root/transaction/context・初期期限・path・
local snapshotをCAS候補へ束縛する。既知baselineの原本と現在選択packageを同一視しない。
選択は一致する候補へ一度だけ束縛し、必要な退避先は欠落を実観測する。
選択recordと必要な参照の正規集合を保存し、全保持物と現在namespaceを再確認する。
候補、選択、保持集合はいずれも署名付き利用者同意や実行許可を代替しない。

## 代替案

選択時に別の新しいsnapshotを暗黙採用する方法、退避名の既存fileを無条件上書きする方法、
元DEBを追跡せず内容hashだけをbaselineにする方法は採用しない。
通常fileへの転換やlinkを既存の内容比較へ押し込まず、別の効果解釈を要求する。

## 影響

内部SDKとCAS派生recordを追加する。共有API/vendor・数学的入力・公開コマンド・
導入済みDBは不変。ファイル適用、pin、GC、実世代公開は行わない。
欠損した保持物をRecheckで再構成しない。失敗後に未参照CAS objectが残り得る。

## 検証と残る条件

実原本と私有root/CASで両選択、更新・通常削除・purge・宣言付き削除・省略、
選択待ち中の編集、退避先の占有/後発作成、保持物欠損、別候補/閉包と期限を検査する。
認証UI、正しい稼働root/intent/所有権のmanaged admission、全属性と全namespaceの選択、
世代保持閉包・durable recovery・root/boot公開は未完。処理内の一回性を再起動間の一回性にしない。
