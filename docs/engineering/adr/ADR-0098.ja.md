# ADR-0098: 観測属性の検査付き読戻し

## 背景

内容選択をroot組立てへ渡すには、CAS内のlocal metadataをlive C handleなしで解釈する必要がある。
内容の採用元と所有者/permissionの採用元は一致するとは限らず、inode/ctimeなど観測値と復元値も異なる。

## 決定

NIACOBS1の独立Ada readerを追加し、raw path、全数値幅、時刻の符号、namespaceと可視xattrを保持する。
metadataと内容objectを既存CASから再hashし、構造・長さ・順序・欠落位置・内容サイズを検査する。
snapshotの保存処理からもreaderを通し、Cから返された内容/サイズとの一致を確認する。
読戻した記録は過去の観測であり、現在のroot/属性の真正性や復元可能性を単独では証明しない。

## 代替案

既存の狭いfile-plan属性へ変換する方法、未知flagを切り捨てる方法、記録欠損をhost fileから
勝手に再構成する方法は採用しない。可視ACLは生のsystem xattrで保持し、archive ACLへの変換を推測しない。

## 影響

新しい内部readerとsnapshot保存後の検査を追加する。既存NIACOBS1の形式、共有API/vendor、
数学的入力、公開コマンドは不変。root適用・metadata変換・特権属性の取得はまだ行わない。
Debian 13の保持済み上流sourceの所有者/permission処理を参照したが、上流コードをコピー/変更していない。

## 検証と残る条件

実snapshotからraw名、負/小数時刻、mode/UID/GID、実POSIX ACL、空/バイナリxattrを読み戻す。
破損field、切断/余剰、順序違反、桁落ち、内容サイズ/欠損と期限を拒否し、既存選択経路も検査する。
特権observer、所有/permissionを含む属性の採用方針、全namespace・実root archive、
認証UI、全managed認可、世代保持/復旧とboot接続は未完である。
