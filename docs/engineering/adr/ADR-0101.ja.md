# ADR-0101: 全幅時刻を保持する設定entry出力

## 背景

root配置の直列化で、設定のraw名・数値owner・全時刻・可視属性を失ってはならない。
固定環境の上流writerへの具体的入力で負の小数時刻の相違とbirthtimeの省略を確認した。

## 決定

通常設定entryのPAX/header prefixをNiaの有界codecで生成する。
全permission bit、数値owner/size、BINARY名、signed nanosecond時刻と生の拡張fieldを保持する。
正規pathと拡張key重複を検査し、予約済み標準fieldは拡張APIから変更できない。
Finishはbuilderを消費し、失敗時は出力を消す。既存readerへBINARY宣言、全signed時刻と
255 byteのpercent-encoded xattr名を扱う検査を追加する。
raw xattrは名前/値が実読戻しで一致するLIBARCHIVE形式へ出力し、既存SCHILY入力を改変しない。

## 代替案

上流writerの観測済みの相違を黙認する方法、mtimeを非負整数へ切り詰める方法、
birthtimeや空/バイナリ属性を落とす方法は採用しない。上流ソースへ独自patchも当てない。

## 影響

内部codecと既存framing readerを拡張する。元root/選択形式、共有vendor、数学的入力、
公開コマンドを変更しない。出力はheader prefixであり、内容やrootを公開する権限は持たない。

## 検証と残る条件

生成tarをnative framingと独立PythonのDecimal/byte比較で読み、scriptなしDEBへ包んで
既存payload readerの内容・時刻・全数値owner・raw xattr・ACL/flagも検査する。
全signed端点、負の小数、BINARY名、長いencoded key、重複/予約field/短い出力とpath拒否を扱う。
元root配置からの全直列化、元属性adapter、実属性適用と全managed認可、保持/復旧・bootは未完。

upstream readerの負の小数時刻変換にも差を確認した。payloadのnative補正は確認したが、
root workerへの同じ補正は未実装であり、次の実適用工程で対処する。
