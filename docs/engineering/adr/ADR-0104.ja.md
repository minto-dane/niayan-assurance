# ADR-0104: 保存属性からの設定entry生成と実効ACL modeの照合

## 背景

設定選択は内容とNIACOBS1/元DEBの参照を保持するが、tar生成へ全属性を渡すadapterが未接続だった。
ローカルのPOSIX ACLはraw xattr、vendorのACLは意味を持つarchive属性であり、単なるbyteコピーでは等価でない。
独立読戻しで、group ownerとmaskが異なるACLについてSDKのmodeと実inodeのmodeが異なることを確認した。

## 決定

Pkg_Configuration_Entry.Prepareは既存Storeの保存原本を再観測し、通常fileのheader prefixをCASへ保存する。
数値mode/UID/GIDと内容のassertionを照合する。元のmtime/atime/ctime/birthtime、raw xattr、ACLとflagを渡す。
vendorのpermission overrideは保存済みローカル観測へ束縛し、chmodと同じowner/group-class/otherを変更する。
named ACLの権限は残す。ACLの表示名からhostのNSSを参照せず、数値identityを用いる。

POSIX access ACLにmaskがある場合、inodeのgroup modeはmaskに対応する。
Pkg_Deb_Payloadの数値modeとworkerのstat照合にこの区別を反映する。
archive_entry_set_modeによる補正は元のgroup-owner ACLも変えるため行わず、ACL本体を独立に保持・照合する。
根拠は[Linux ACL仕様](https://man7.org/linux/man-pages/man5/acl.5.html)と
[採用上流のACL実装](https://github.com/libarchive/libarchive/blob/v3.7.4/libarchive/archive_acl.c)。

raw access ACLをsemantic ACLへ変換し、regular fileのdefault ACLやvendor raw ACLの重複表現は拒否する。
上流text readerが飽和させるC int範囲外のnamed identity、未知のactive statx属性、表現不能flag、
未解決のローカル複数linkを拒否する。flagsは上流APIの往復一致を要求する。extent配置はsettable効果にしない。
失敗時prefix/sizeを消し、期限とUID0拒否・同一Store予約を維持する。

## 代替案

内容だけの出力、ACLを削除してmodeだけ保持、named権限をmaskへ切り詰める方法は元の意味を失う。
上流sourceのpatch、host account名の参照、未知属性の黙認、実行許可を常時成功にする方法は採用しない。

## 影響

公開コマンド、保存観測・選択・root manifestの形式は不変。新adapterは内部SDKであり、本番認可や公開APIではない。
従来誤ったgroup modeを含んだ派生metadataは再観測結果が変わる。旧hashを新hashへ暗黙更新せず、
原本・履歴を保持する。対象旧計画の移行・復旧受入は未認定で、通常の新計画・認可が必要である。
worker packageを0.2.2とする。上流source・共有vendor・数学的入力は変更しない。

## 検証と残る条件

実ローカルACL・空/binary xattr・raw名、vendor、既存権限を継ぐ更新とbackupを検査する。
NIACOBS1と元DEBを独立Pythonで読み、生成tar・native payloadと比較する。
使い捨てVMの隔離ext4で導入済みworkerへ渡し、内容・mode/UID/GID・ACL/xattr・flags・実mtime/atimeを照合する。
既存workerのroot・inode種別・時計・拒否caseと、パッケージ再現性を変更境界の回帰に含める。

prefixは全rootではない。全root streaming/保存、選択のlive再検証・保持閉包・managed認可、特権observer、
全inode/DEB効果、実root/boot・復旧・完全置換ISOは未完。隠れた属性の完全性やctime/birthtimeの復元は主張しない。
