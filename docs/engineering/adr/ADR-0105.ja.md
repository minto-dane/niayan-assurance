# ADR-0105: 設定済みrootのstream生成と全参照の保持

## 背景

原本rootと設定選択の配置、属性付きprefixはあるが、完全なroot tarと保持記録へ接続されていない。
元tarの全展開だけでは選んだ削除やローカル保持が消える。最終fileだけから参照を集めると
削除の選択や旧vendor原本を失う。全archiveをメモリへ集める方法も実rootの容量に適さない。

## 決定

Pkg_Configured_Root.Buildは新しく配置を検証し、元spanと設定prefix/contentを二回のstreamでCASへ保存する。
directoryはroot/親を先行、base nondirectoryは元順とhardlink依存を維持し、設定はpath順で追加する。
変更を横切るhardlinkは既存の配置検査で拒否する。sourceのhash/stat、正確な長さ・padding・終端を検査する。

NIACRT01に元binding、root/transaction/context、architecture、生成tar、全choice、各prefix/contentを記録する。
NIACRC01はcatalog/choiceの既存閉包の和集合と、元/生成manifest/archive・prefix/content・閉包自体を
strict sorted unique集合として保存する。削除の選択も保持する。返却前に全choiceを再確認する。

Verifyは全保持objectを先に検査してからBuild結果を比較する。欠損を自動再構成して正常にしない。
再構築は明示したBuildで行い、履歴・元hashを上書きしない。

## 代替案

元rootへ直接上書きする方法、tar全体のメモリ保持、削除設定を原本から再混入する方法、
新しい管理DBや常時成功callbackは採用しない。既存NIAROOT/世代形式を無版で変更しない。
既存の属性読取・Store writer・所有権・設定観測を再利用し、上流sourceは変更しない。

## 影響

新形式は内部生成物であり、既存世代のroot hash欄へ暗黙に渡してはならない。
524288 entry、4096 choice、8 GiB以下のcaller limit、元sourceのframing/名前量制限と資源guardを維持する。
本文は64 KiB bufferで流し、source/memberの索引は有界で保持する。全同期I/Oには外側の資源制限も必要である。
choice参照は呼出し中だけ借り、同じStoreを保持する。失敗時全digestを消すが完了CAS objectは残り得る。
共有vendor・数学的入力・公開管理インターフェイス・特権worker本体は不変。

## 検証と残る条件

ローカル保持、vendor採用、独立hardlink chain、大きな未変更本文、削除維持、復元、空fileを扱う。
原本・選択・最終tarと閉包集合を独立Pythonで照合し、VMで最終namespaceと実inodeを確認する。
期限、live変更、容量と保存root欠損の拒否、明示再構築の同一性を検査する。

live proposalを再起動後に復元するloader、世代pin/GC/保持・実root準備・公開/bootへの接続、
全過去設定/隠れた属性/inode/DEB効果、認証UIと本番provider、完全置換ISOは未完。
この生成器とfixtureの成功を本番認可・復旧・全実FSの認定にしない。
