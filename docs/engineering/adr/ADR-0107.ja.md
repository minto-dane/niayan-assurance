# ADR-0107: 新しいCAS予約での設定選択の再観測と全root照合

## 背景

世代処理はengineがCASを開き直す。既存proposal/snapshotは同じ開いたStore予約を継続する契約なので、
保存参照loaderだけではこの境界を越えて設定を検証できない。古い予約番号の比較を外したり、
保存hashの一致だけで現在の設定を確認済みにしたりしてはならない。

## 決定

Pkg_Conffile_Choice.Reobserveは新しい予約の下で、期待root/transaction/contextと保存choiceを受け取る。
保存記録と全列挙memberを先に検査し、通常のPrepare/Resolveを使って原本・宣言・現在のinode/属性/内容・
退避先を再観測する。proposalの比較では新規観測の期限fieldだけ、decisionでは新proposal参照だけを除外し、
その他の全byteを一致させる。旧期限は履歴であり書き換えない。返すのは現在の予約で取得した観測sessionであり、
期限が異なればhashも異なる。同じ有限期限を指定した場合も、保存されたsessionを使い回さず再観測する。

保存choice閉包は、再観測で導出したsource集合に旧proposal/decisionを加えた集合と厳密に比較する。
sourceの役割をrecordの役割から別に保持する。同じdigestが内容とrecordを兼ねても、平坦集合から
session IDを引いて必要なsourceを失うことはない。既存wire形式とPrepare/Resolve/Recheckの契約は変えない。

Pkg_Configured_Root.Verify_Currentは保存rootの全参照検査を先行させ、期待する元root/catalog/closure、
root/transaction/contextとarchitectureを確認する。全choiceを現在のrootから再観測し、通常のBuildで
原本由来の閉包・所有権・配置・全tarを検証する。新しいmanifestのchoice参照だけを一時比較bufferで
旧参照に対応付け、それ以外の全byteと最終tar digestを一致させる。旧記録への保存や置換は行わない。
最後に全新規choiceをlive再確認する。保存されたchoice閉包の意味と、元catalog閉包の意味がそれぞれ
検証されるため、先行Loadのexactな和集合の検査を実際のsourceへ接続できる。

## 代替案

同じStoreを要求する既存契約の撤廃、古いproposalの復活、deadlineや履歴hashの永続上書き、
任意の保存tupleを常時成功で受理するcallback、保存済みtarを原本/現在の設定と照合せず使う方式は採用しない。
NIAGEN05の欄へ新しいroot形式を暗黙に受け入れさせない。上流sourceは変更しない。

## 影響

新APIは現在の観測を行うため、新しい未pinのCAS観測記録・派生成果物を作り得る。
読取専用Loadとは異なる。既存の保持member欠損はそれより前に拒否する。失敗時は出力/sessionを消す。
返却するarchiveは既存保存rootのdigestであり、新観測記録に置き換えた世代を発行するAPIではない。

新しい観測期限は同意・失効・新規要求の真正性・復旧実行許可を更新しない。callerは期待scope、root FD、
保存選択と利用の認可を別途確認し、現在のroot/CAS予約を保持して使用境界で再検証しなければならない。
mount/inode/属性のidentityは厳密に比較する。OS再起動でmount identityが変わった場合や、設定適用後の
accepted状態の復旧を「変更なし」として扱うことはできない。その移行・復旧には別の規則が必要である。

## 検証と残る条件

通常選択試験に新しい期限での再観測を接続し、各operationの元/属性/backupを通常経路から導出する。
全root試験では独立期待context、保存root欠損を確認する。同じmount namespaceの新プロセスでCAS/rootを開き、
現在一致する空fileと、過去5種類の観測の拒否を区別する。保存構造としては受理される所有権binding、
設定prefix、root byteの不整合を全root照合では拒否する。旧期限1の観測も現在の全条件が一致すれば
新規観測として検証できる。過去のCAS memberはすべて元hashのままであることを確認する。

この現在観測APIを世代保持・実root準備・公開/復旧の各phaseへ接続すること、期待FD/scope/同意の本番認可、
boot identityの移行、全DEB効果、完全置換ISO、全言語翻訳は引き続き未完である。
