# ADR-0110: 固定した実rootの非更新再検査

## 背景

保持archiveの論理的公開と、実rootの展開完了は異なる。bankのinspectは過去の記録を返すだけで、
再起動後の内容やnamespaceを確認しない。実root切替を接続する前に、期待archiveと展開済みの実物を
現在の予約の下で照合する経路が必要である。検査自身が内容・属性を修復して不一致を隠してはならない。

## 決定

既存内部workerへ最後の引数として--verifyを追加する。元の展開引数と挙動は維持する。
対象は保護されたstage親のrootで、検査側から実際にread-onlyかつnodev/nosuid/noexecと観測できる
mountを必須とする。workerやサービスはfreeze/remountを代行しない。呼出し側がbank/CAS予約と
整合したmount管理・全writerの停止を維持する。read-only bind viewだけでは別viewのwriterを停止できない。

workerは期待tarの全byteを二回hashし、同じ時刻cursor、内容digest、数値owner/mode、宣言時刻、
ACL、flagsのset/clear条件、link先、device番号を使って照合する。再検査ではxattr集合も双方向に
照合し、未宣言属性を拒否する。pathは一意で、有界の相対名とし、openat2のBENEATH/NO_SYMLINKS/
NO_XDEVで各項目を確認する。全期待directoryを列挙して余分な項目を拒否し、非directoryの実inodeを
分類して、各groupに一つの原本と宣言hardlinkだけが存在し、実nlinkがその件数と一致することを要求する。

再検査ではdisk writer、root時刻設定、symlink時刻復元、syncfsを呼ばない。read-only mountのため
読取に伴うatime更新も行われない。継承reservation FDの保持、chroot、seccomp、資源/期限の制限は
元のworkerと共通である。成功応答はverifiedとarchive/entry数、実mount ID、device/inodeである。
これは署名や公開許可ではなく、保持すべき物理観測である。

Bank.verifyおよび二FDを伴うcanonical JSONの{"verify": request}を追加する。サービスは現在の
peer UIDと実CAS予約を検査し、saved extracted/resultと現在worker hashの一致を要求する。
期待stage/generation/root_manifest/archive/size/entries/versionは元intentに一致しなければならない。
現在のdeadlineだけを新規観測の期限として受け付け、古いintentを変更しない。元の記録・root FDを
保持し、workerのmount/device/inodeをサービスのFDと照合し、応答後もpathの同一性、read-only/
mount policy、予約、saved結果と期限を確認する。元intent/resultを書き換えず、physical_revalidationと
観測を応答に付加する。inspectのphysical_revalidation:falseは維持する。

## 代替案

過去のextracted記録を再利用する方法、再展開して修復を隠す方法、書込可能treeのatimeを検査後に
復元する方法、既知のpathだけ調べて余分な項目を見逃す方法、treeと異なるmountの観測を受理する
方法は採用しない。上流libarchiveやkernelを改変せず、全DEB効果をこの照合へ暗黙に含めない。

## 影響

サービスの開発版を0.3.0へ増加する。旧worker hashで作ったrootは自動移行せず、このAPIでは拒否する。
再構築または別の明示的migration判断が必要である。未宣言のLSM labelも勝手に信頼せず拒否する。
再検査は原本のctime/birthtime一致や全MAC policy、未宣言flagsの意味を認定しない。
返す観測はmount変更やwriter再開後の許可ではない。bankが解除されるまでの継続的な権限伝達、
SDKからの期待worker/認証provider接続、freeze操作の本番管理、実root/boot切替は別に実装する必要がある。

## 検証と残る条件

使い捨てVMのext4で実DEB packageを導入し、実workerとFD RPCを使う。正常root、内容/欠落/余分な項目、
xattr/mode、外側hardlink、symlink先、子mountの9経路、書込可能rootと異なるgenerationの拒否、
サービス再起動と実UIDからのRPCを確認する。全read-only treeの内容/属性と元記録の前後一致、
呼出し元のleaseが保持されることを確認する。従来の展開・bank試験も変更境界として確認する。

本番の独立認可・供給/設定provider、全writer排他、mount切替/bootとその復旧、全DEB効果、GC、
完全置換ISO、全言語翻訳は未完である。人工fixtureと限定profileの受入を本番認定にしない。
