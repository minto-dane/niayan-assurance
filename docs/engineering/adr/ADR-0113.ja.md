# ADR-0113: 専用bankの明示配備と起動時device照合

## 背景

filesystem全体のread-only化には専用bankが必要だが、従来のbootstrapは共有filesystemのbind mountを
作っていた。mount IDとdevice番号は再起動を越える選択情報ではなく、device名だけの再使用も不十分である。

## 決定

0.5.0のbootstrapはroot所有0600の明示planでGPT partition UUID、ext4 UUID、正確な容量を受け取る。
root管理のudev pathからblock FDを保持し、kernel容量とcacheを迂回したblkid probeの実metadataを照合する。
partition以外、既存mount、現在のroot device、形式/UUID/容量の不一致を拒否する。formatやpartition操作は行わない。

既存の排他的bootstrap intentと完了記録へplan全体のhashを束縛する。既存core/bank/記録/drop-inは上書きしない。
明示installerがPARTUUIDを使うmount drop-inを作成・同期し、通常mountをro,nodev,nosuid,noexecとする。
配布unitにbind fallbackを残さない。初期化だけRWへ変更し、元のbank provisionerを呼び、finallyでROへ戻す。
空でないrootやlost+foundのrecovery内容を削除しない。現在照合に成功した場合だけ完了記録を作る。

起動前の独立oneshot guardがplan/drop-in/初期化記録、実block deviceとmounted root、bank記録の存在を照合する。
準備serviceはguardの成功を要求する。guardはread-only probeのための最小権限と資源制限を持ち、準備serviceの
capabilityやdevice viewは拡大しない。unitは自動有効化せず、独立controllerの代わりに処理を許可しない。

## 代替案

共有filesystemのremount、device pathだけの永続化、UUID symlinkだけへの依存、自動format/移行、
欠損記録の再生成、既存mount overrideの上書きは採用しない。上流systemd/util-linuxへpatchは加えない。

## 影響

旧bind bankと旧完了記録は新しい起動条件を満たさない。自動migrationは提供しない。
UUIDは暗号学的認証ではなく、clone/hotplug、特権mount/raw device writerには別の管理排他が必要である。
LUKS/device-mapper/RAIDの別profileと完全置換ISOのpartition recipe/UIは未対応である。
正常終了や通常例外のfinallyはSIGKILL/電断に代わらない。再起動のRO mountと完了記録の必須検査で
未完状態からのservice開始を拒否し、自動rollback/repairを行わない。kernel I/Oの厳密な時間上限は主張しない。

## 検証と残る条件

使い捨てVMに追加した明示GPT/ext4 diskで実native initializerと導入済みunitを使用する。
plan欠損、UUID/容量違い、既存core/bank/初期化記録、再初期化を拒否する。
再起動後の同じbank記録、RO mount、guard経由のservice開始、plan変更によるservice拒否、lock欠損の非修復を確認する。
試験用の明示復元を製品の自動復旧に数えない。0.5.0の別directory二重buildと実導入を確認する。
初回に検出したguard unitのinstall指定漏れを修正し、最終packageで検査する。失敗入力とログは保持する。

本番controllerの認証/RPC・全寿命のdevice/mount排他、bank slot管理、効果直前の再検査、実root/boot切替・復旧、
全DEB効果、GC、完全置換ISO、全言語翻訳は未完。既存SDK/worker/数学的入力の不変な全suite/証明を反復しない。

根拠はdistribution/native/bank-device.ja.mdのDebian公式blkid/systemd.mount資料を参照。
