# ADR-0115: root supervisorのnative session transport

## 背景

初回bankのcontrollerはroot管理面用だが、既存世代SDKは非rootの隔離staging用である。
両者のUID境界を解除すると、既存の認可・予約・所有者の前提を破壊する。独立したsupervisorから
controllerを呼び、同じ接続を保持するnative APIが必要である。

## 決定

Pkg_Root_Sessionのlimited controlled型と専用C transportを追加する。Openは明示したscope、worker/device/boot/bank
pinと借用archive/CAS FDだけを正規packetへ送る。root peerと各応答のroot UID/同じsender PIDを確認する。
応答全体の正規bytesを照合し、初回root inodeだけを未独立検証の観測値として受け取る。
受信FDの採用、再接続、再送、期限延長、常時成功の認可providerは提供しない。

socketはCLOEXEC、作成PIDへ束縛する。使用中OpenはConflict。Observeは新FDと元期限を使い、失敗は観測を
無効にするが明示Closeまで自身の接続を残す。CloseのEOFとFinalizationの切断を区別し、uncertain結果を未実行にしない。
Held/Observationを独立mount証明、世代認可、起動許可へ変換しない。既存非root SDK/API/永続形式は不変。

## 代替案

既存非root transportのUID拒否を解除する方法、単発RPCごとに接続し直す方法、応答inodeをそのまま
独立期待値にする方法は採用しない。既存の権限境界とcontrollerの全寿命予約を維持する。

## 影響

root専用の内部APIとC/FFI境界が増える。正規応答を明示形式に照合するため、将来のprotocol変更は
版付き契約として更新しなければならない。既存worker/unit/packageの権限とbytesは変えない。

## 検証と残る条件

固定containerでC/Adaをcompileし、人工seqpacket peerで応答のscope/属性/期限、過大/非正規/control、FD解放、
UID/PID変更、forkコピー、Close/期限切れ/観測変化、Ada Finalizeを検査する。C境界へsanitizerを適用する。
使い捨て実GPT/ext4 VMでは受入0.6.0 controllerと新transportの準備/観測/Closeを接続し、独立root FDと
新CAS OFD、保持Bank、ROと元tree/記録の不変を確認する。対応source/binaryを記録する。


独立root supervisorのsite認可/供給/利用者同意・取消寿命、非root世代SDKへの認証済みhandoff/observer、
外部特権writer排他、bank slot/GC、実root/boot切替と復旧は未完。root管理面は信頼主体で、credential/PIDの
照合だけでその侵害を防ぐとはしない。人工peerの成功を本番admissionや物理故障の受入へ置き換えない。
