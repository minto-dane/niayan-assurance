# ADR-0118: 非特権世代処理の明示的なroot handoff境界

## 背景

世代SDKは旧サービスへのRPCを直接呼び、root supervisorの保持sessionへ実FDを渡せない。
非root SDKのUID制約や認可/予約を解除して接続してはならない。

## 決定

Prepare_Root_Usingの必須transport引数を追加する。旧Prepare_Rootも同じ実装へ委譲し、
前後の認可/内容/設定照合とstage/root/CAS予約を共通化する。送信後の失敗はIndeterminateを維持する。
Pkg_Root_Handoffはrootが作成したprivate seqpacketの借用FDを使い、実root peer pidfdと応答のUID/PIDを照合する。
元期限・固定192-byte要求・SHA-256応答と1回の送信試行を保持し、別socketへの再接続やretryを行わない。

root_handoff.Channelはrootが起動した実direct childをpidfdとwaitid(WNOWAIT)で照合する。
各messageのPID/UID、独立した期待scope、2 FDと正規形式を確認する。子孫/別scope/過多FD/取消/期限を拒否し、
自身の受信FDコピーを閉じてから応答する。root controllerや認可を自動的には呼ばない。

## 代替案

UID拒否の解除、client申告UID/PID、受信scopeをそのまま期待値にする方法、socket到達だけの認可、
元予約を解放してからの送信、成功replyによる起動認定を採用しない。

## 影響

これは準備要求の内部transportで、public CLI/listener/launcherは追加しない。
呼出側は現在供給/世代admission、operator認証、正確な同意と取消を保持し、root sessionの準備と
独立root観測を終えてからcompleteを呼ぶ必要がある。再検査handoffと稼働daemonへの接続は未完である。
借用channelの所有者は物理排他の全寿命を保持する。SDK Closeはduplicateだけを閉じ、remote cleanupを証明しない。

## 検証と残る条件

v5/v6の既存世代fixtureでtransport前後の拒否、全予約、post denialと例外の不確定扱いを検査する。
private root containerで実UID/pidfd/SCM、要求/応答/FD/取消/子孫/期限/一度限り/Ada ABIを検査する。
これは人工認可の試験であり本番admissionや実root準備の新規受入ではない。ADR-0117によりC全体の形式検証と規則適合も未完である。
