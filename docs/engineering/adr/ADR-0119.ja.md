# ADR-0119: root handoffの有限状態と失敗後の資源解放

## 背景

特権Pythonにもimplementation-assuranceの基準を適用する。root Channelの複数の真偽値は
一回限りの受信・応答を表現するが、閉鎖後の呼出しと例外後の状態が型で明示されていない。
受信FDのcloseがOSErrorを返すと、残る受信FD、pidfd、socketの解放へ進まない経路がある。

## 決定

STARTING/READY/RECEIVING/RECEIVED/COMPLETING/COMPLETE/FAILED/CLOSEDのEnumを用い、
実runtimeのtransition関数だけで通常の状態変更を行う。受信・完了の試行を外部I/O前に記録し、
失敗からREADYへ戻さない。閉鎖は冪等で、閉鎖後の操作はI/O前に拒否する。
成功応答は受信FDコピーの解放と現在資格情報・取消の再確認後だけに送る。
元の最大600秒期限に加え、各waitは最大1200回のpoll呼出しで拒否する。
boottimeのms変換には整数nsを使い、浮動小数点丸めを介さない。

FDは所有集合から取り外して一度だけcloseする。OSErrorでも残りの解放を試み、入力FDの
複数エラーはExceptionGroupで返す。close本体はfinallyでpidfd/socketも解放する。
Linuxではclose失敗後の同じ番号への再試行が、既に再利用された別FDを閉じ得るため行わない。
外部所有の原本FDを閉じたり、callerのchildをreap/killしたりしない。

## 代替案

真偽値のまま個別条件を追加する案では、閉鎖を含む状態組合せの説明が分散する。
一つの有限制御関係へ集約し、外部効果との対応箇所を限定する。

## 影響

内部Channelの状態表現と異常時解放が変わる。要求/応答wireとC/Ada ABIは変更しない。
物理効果や管理認可の追加は行わない。

## 検証と残る条件

root_handoffと有限検査器を固定mypy 1.15.0-5でstrict、Any式/明示Any/未解決Any禁止、
到達不能診断に通す。recvmsgの未使用addressだけはstdlib stubのAnyをobjectとして受け取り、
型無視やcastによる認証の省略はしない。チェックはnative-checkの必須工程とする。

実transition関数に独立した履歴counterを組み合わせて全到達状態を探索し、
ack <= complete attempt <= accepted receive <= receive attempt <= 1、失敗/閉鎖後の再利用禁止、
成功経路と全phaseの到達を検査する。深さ上限による探索の省略はしない。
状態再開と受信前completeを許す負の対照で検査器が失敗することも確認する。
Python最適化でassertが消える設定は拒否する。

解放後EIOと同じFD番号の実再利用、pidfd解放エラー、応答前解放失敗、閉鎖/受信失敗後の操作、
poll途中の取消、poll予算を検査する。既存の実root/非root、pidfd、SCM、scope、Ada往復も回帰確認する。

## 残る条件

有限探索が証明対象とするのは制御関係と履歴である。I/O、割当て、Python interpreter、
全FD寿命、他thread/非同期中断やkernelの停止時間を含む全runtimeの形式証明ではない。
OSの最終確認とsendの間を原子的な取消境界とは扱わない。物理遮断はroot session側の責務である。
本番admission、正確な計画同意、供給、root session/独立観測の接続とC全体の適合は引き続き未完。
