# ADR-0120: root準備の独立サービスを廃止し保持sessionへ集約する

## 背景

旧root-preparationは非特権coreから直接要求を受ける独立した特権socketである。
後継root-sessionは監督側のroot peerを限定し、bankの予約・worker・凍結の寿命を保持する。
旧経路には比較試験の利用箇所があるが、将来の製品で必要な別の役割はない。
利用者は不要な旧実装を廃止し、ミッションクリティカル性、ACID、セキュリティ、
性能、保守性から判断する権限を明示した。

## 決定

旧service/socket、Bankのlistener/connection処理、C/Adaの専用RPC、専用VM bridge、
旧namespaceだけで使用した配布用devディレクトリを削除する。後継へのfallbackを作らない。
Bankのprepare/verify/inspect、永続intent/result、排他、bootstrap、FrozenRootは後継が使用するため残す。
既存package名、保護policyのpathとbank永続形式は共通処理の識別子であり、不要な改名やデータ変換をしない。
過去のhash付き証跡・対応ソース・ライセンスは現行実行経路と区別して保存する。

SDKはPrepare_RootとReinspect_Root_And_Holdを各一つにする。transportを必須generic引数とし、
Socket_Path引数、Using別名、既定接続先を廃止する。独立Observe_Rootも必須のまま維持する。
物理identityの型は通信実装から独立したPkg_Root_Identityへ移す。
全native認可、現在設定/保持内容、stage/root/CAS予約、実archive FD、元期限と前後観測を共通処理に残す。
transport呼出し後の拒否/例外はIndeterminateであり、再送・経路切替はしない。

| 観点 | 判断と限界 |
| --- | --- |
| 原子性 | intentより先に展開しない。部分rootを公開・再初期化せず復旧対象にする。旧受付撤去だけではroot/bootの原子的切替は完成しない。 |
| 整合性 | 入力・元記録・現在観測の照合を残す。DEB全効果と本番admissionは別の未完条件。 |
| 分離性 | bankを保持するcontrollerに集約し、並行する旧特権受付を削除する。全writer/GC/slotの排他はまだ未完。 |
| 永続性 | intent/resultとfsyncを維持し、停止後の欠損を成功にしない。媒体・電源障害全体の保証ではない。 |
| セキュリティ | 非特権直接socketと専用C/FFIを削減する。root-sessionのpeer/各message本人確認、pidfd、期限、RO再封鎖は維持する。 |
| 性能 | 旧daemonを配布・起動する可能性と重複wireの維持をなくす。測定なしに性能向上の数値は主張しない。 |
| 保守 | 共通処理と必要な耐障害性試験を維持し、試験のための製品入口を残さない。 |

制御面packageの更新は対象OSを停止したオフライン環境で行う。preinstはsystemd稼働環境での
upgrade、設定の残る再導入、既存controller/初期化済みstorageへの導入を拒否する。
新規の空VMへの初回導入は可能だが、サービスの自動起動/初期化はしない。
瞬間的なActiveState検査やsocketだけの停止では再起動競合と既存workerを排除できないため、
稼働中の自動移行は提供しない。旧0.7.0のmaintainer scriptも確認対象とし、更新前のprermが
勝手にworkerを停止しないことを実packageで検査する。オフライン対象には稼働OSの/runを共有しない。
新packageで旧unit filesは所有物から消え、通常のpackage更新で除去される。
管理者独自unit/drop-inや永続記録を推測で削除しない。独自unitの撤去は復旧環境での別の明示作業とする。

[Debian maintainer script順序](https://www.debian.org/doc/debian-policy/ch-maintainerscripts.html)と
[Debian 13のdh_installsystemd](https://manpages.debian.org/trixie/debhelper/dh_installsystemd.1.en.html)
に従う。これは制御面packageの移行条件であり、稼働製品の第二のpackage authorityを許可するものではない。

## 代替案

比較試験のために旧serviceを残す案は、別の書き込み受付と未証明Cを維持する費用に見合わない。
同じSocket_Path APIへ特別値を渡してsessionを選ぶ案や旧wrapperの並存は責任を曖昧にする。
未リリースの内部APIなので全呼出元を移行する。公開コマンドと上流ソースは変更しない。

## 影響

旧serviceのVM bridgeを廃止する。bankの排他/誤予約/重複拒否/intent後のprocess停止試験は
共有Bank試験へ移し、実peer/FD/worker/切断/期限/停止後のROは既存root-session試験で扱う。
SDKの三予約・期限後の無効化と明示解放はtransport指定fixtureへ移す。
重複したcheck_service_deployment.pyを削除し、bootstrap/device/再起動はcheck_bank_device.pyへ、
有効な実要求でのbank lock/CAS lock/policy欠損拒否はcheck_root_session.pyへ集約する。
過去の旧経路の受入を新経路の統合受入へ読み替えない。
旧service専用の既存store/追加socket引数もfixture mainから除去する。

版付き世代/journalの読取・受理済み記録復旧は現行APIと試験が使用するため、単に旧版という理由では消さない。
初期化器、共有vendor原本、対応ソース、旧ライセンスも独立ビルド/復旧/配布義務に必要である。
コンパイル用imageとQEMUを含むVM用imageは役割が違う。版を記録して必要な工具として保持する。
終了済みの今回のVM overlayと失敗試験cacheは、証跡保存と利用者不在の確認後に削除する。

## 検証と残る条件

v5/v6のnative fixtureで、事前認可/観測拒否、scopeと独立期待値、実FDと三予約、
成功handleの非置換、拒否/例外/事後変更での解放、期限後の予約維持を確認する。
UID0はobserver/transport前に拒否する。これは人工identityであり実mount観測ではない。
packageは旧unit/dev/RPCの不在、オフライン更新のファイル除去、稼働環境での更新拒否を検査する。
実施済み/未実施は対象sourceに束縛した証跡を参照する。

SDK→root handoff→保持sessionの本番admission/正確な同意/独立観測/物理取消は未接続。
全writer排他、実root/boot切替と復旧、全DEB効果、完全置換ISO、全言語翻訳は未完。
SPARK対象外Adaと特権Pythonの試験を形式証明としない。残るC全体/FFI/runtimeの厳格基準を維持する。
