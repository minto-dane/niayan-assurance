# ADR-0121: niayan公開と採用コマンドの配布

状態: proposed-for-review。利用者はniayan名での公開と、不要な代替入口の撤去を許可した。

## 背景

採用管理コマンドはソースだけにあり、旧public aliasが配布される不整合があった。

## 決定

公開workspaceはminto-dane/niayan、8つの独立repoはniayan-*とする。
OSの表示、os-release、GRUB、ISO名とliveユーザーへniayanを採用する。
内部形式・DEB所有者・署名domain・原本履歴は名称だけを理由に変更しない。
0.2.0の識別packageは従来0.1.0を上書き配布せず、新しい版で区別する。

機能を持たずMissionctlを呼ぶだけのpublic nia aliasを撤去する。代替aliasは作らない。
内部管理工具は維持し、実装fingerprintと人工fixtureを正本工具で更新する。
niayan-managementには採用した12入口、必要なmoduleと翻訳だけを同梱する。
単一の原本exportを利用し、source-inputsとimage manifestが配布の全入力を追跡する。
別の導入台帳、特権launcher、既定の許可policy、外部工具のラッパーを導入しない。

## 代替案

旧aliasの保持は不要な操作入口を残すため採用しない。全sourceの名称置換は永続形式を破壊するため行わない。

## 影響

### ACIDと権限境界

この変更は稼働catalogやrootを更新するauthorityを増やさない。既存ローカル成果物操作と
認証付き取得が使えるようになる。未接続の導入済み操作は従来通り失敗を返す。
公開CLIの存在・parser成功は供給/同意/全効果検査を省略する根拠ではない。
root-owned実装をpython3 -Iで起動し、利用者のmodule検索環境を読まない。
翻訳は実装の保護されたcatalogからだけ読み、操作の機械識別子と分離する。

## 検証と残る条件

配布を一つのcheckpointとし、実DEB構築、隔離した配置で公開コマンドと翻訳の動作、
管理器のalias撤去後の構築、生成物と配布manifestの整合を確認する。
不変のC/FFI/SPARK実装に対する全証明を反復しない。全製品の出荷前受入は別に行う。
実認可・更新器・起動/復旧・全DEB効果・全言語・実機認定はこの変更で完成しない。
