# ADR-0122: root worker実行中の取消と有限の資源寿命

状態: proposed-for-review。REQ-159 / HAZ-146 / FAULT-159。

## 背景

controllerは展開・物理再検査の子をcommunicateで待っていた。その間は依頼元pidfdと
接続を監視せず、出力量を受信後に検査し、異常時には直接の子だけを終了していた。
保持した認可の寿命を実処理へ接続するには、実行中の監視が必要である。

## 決定

固定された内部workerの起動をroot_worker_monitorへ集約する。依頼元socket/pidfd、
元のCLOCK_BOOTTIME期限を起動前、待機中、返却前に確認する。frozen応答前に次のpacket、
EOFまたはpeer終了が観測されたら取消として扱う。packetを受信しないため追加のSCM_RIGHTSを
取得しない。公開コマンド、任意実行program、既定の認可や再試行経路は追加しない。

workerは専用session/process groupで起動し、既存の親死亡signalとservice cgroup内に置く。
waitid(WNOWAIT)で終了を観測し、leaderをreapする前にgroupへSIGKILLを送る。
PID予約を解放してから同じ番号へkillpgする競合を避ける。STOP完了後だけREAPへ進み、
再起動しない。reap待ち上限は5秒、出力はstdout 4096 / stderr 1024 byte、入力は4096 byte。
非blocking pipeと100 ms以下のpoll、16,384回の有限event予算、600秒以下の元期限を使う。
容量超過・I/O異常・終了不確定は成功へ変換しない。

取消後もroot-session.jsonとbankのintentを維持し、既存finallyのRO remountを行う。
不確定な効果をrollback完了と表現せず、同じbankを自動再利用しない。
配布版0.9.0へmoduleを明示追加し、live更新禁止は維持する。

## 代替案

期限までcommunicateで待つ方式では接続取消が処理へ届かない。direct childだけのkillでは
停止中のnative childを含めた処理群の終了を確認できない。別daemonや追加の公開取消APIは不要。

## 影響

型付きmonitorの状態遷移は実装と同じ関数を有限全探索し、独立の履歴で一回の起動、
停止前reapの禁止、終端からの再開禁止を検査する。これは有限制御の検査であり、
Python interpreter、全OS I/O、signal配送、全writer排除の形式証明ではない。

kernelの終了不能I/O、process groupから離脱した異常な子、第三者の特権writerは
killpgだけでは排除できない。固定workerが別sessionを作らず、外部reaperがこの子を
回収しないことを前提とする。unitのKillMode=control-group、独立seal service、
first-use barrierを維持する。RO remountのkernel待ちそのものに時間保証はない。
他のroot writerまで停止したとは応答しない。本番の認可・同意接続と全runtime証明は未完。

## 検証と残る条件

変更境界を一つのcheckpointとし、strict typing、実プロセスの接続断/packet取消/依頼元死亡、
停止中の子孫終了、出力上限、期限と通常終了、有限制御を検査する。専用VMでは実packageを
導入し、実native展開workerの途中停止後に接続を閉じ、終了・RO・attempt保持・再要求拒否を確認する。
入力hashと実行結果は別の証跡へ保存し、C/SPARK不変部分の全証明を反復しない。
