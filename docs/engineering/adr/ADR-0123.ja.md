# ADR-0123: 独立供給方針の明示的な初回配備

状態: proposed-for-review。REQ-160 / HAZ-147 / FAULT-160。

## 背景

Pkg_Site_Supplyは保護された現在方針と独立floorを検査する実readerを持つが、
installer用の初回配備はfixtureにしかなかった。既存の読取工具も公開用のplan/mapを要求した。
配備検査のために架空の公開contextを与える必要はない。

## 決定

内部pkg_supply_observeに--planningを加え、既存Open_Planning/Observe_Planningを使う。
公開contextを受ける既存七引数の動作は維持する。planningのMapはzeroであり、
成功もexecution_permit=falseを返す。wire decoder、鍵検証、時計/所有権/現在値のreaderは共通のまま。

root-preparation 0.10.0に内部supply_initialize.pyを配布する。administrator/installerが
独立に指定したroot/request identityと、root所有で保護された方針・floor原本を要求する。
鍵、scope、serial、時刻下限、floor hashの自動生成はしない。root所有を運用上の配備authorityと
する境界であり、独立した署名やhardware anchorをこの工具が検証したとは表現しない。

初回記録をO_EXCLとfsyncで保存し、新規の固定supply/trust directoryに原本をstageする。
保護した実ELFのFDをpinしてnia-pkgとしてnative読取を実行する。prlimitと一時fileで
stdout/stderr各64 KiB、CPU5秒、親の待ち8秒を制限する。native自身の期限は5秒。
本文上限は方針20,536 byte/floor72 byte、pathは4096文字/128区切り以内。

native検査後、方針、floorの順に公開する。linkによるno-replace、両directoryのfsync、
pending側unlinkを使う。二つのlinkが残る間は既存native readerが拒否する。
floorの完全hash照合により、初回の不完全な組を受理しない。floorまで公開されてから
完了記録前に停止した場合には、整合した組が既に読める場合がある。これは不確定な完了であり、
rollbackや未実行とは扱わない。最終native再観測と完了記録の耐久化後だけ成功を返す。

既存directory/attempt/completeがある場合は上書き・再初期化しない。失敗時のpendingと記録は
維持し、別の認可された復旧/更新が必要である。欠損を自動修復するserviceは追加しない。
FD解放エラーで旧番号を再closeせず、取得済みの残るFDの解放を試みる。

## 代替案

Pythonにnative wireの意味検査を複製しない。原本からfloorを生成して自己承認しない。
既存方針のin-place更新と自動rollbackは、読取中のproviderや古いfloorとの関係が別の
管理要求になるため初回配備に含めない。新しい公開管理コマンドは不要である。

## 影響

公開後の可視性と応答の有無を区別する。完了記録はexecution permitや署名証拠ではない。
原本の意味不正、observerの欠損/不適合等でもstage後のattemptは残り得る。初回配備は
対応するpkgcoreとroot-preparationを導入したinstallerが行い、記録を消して再試行しない。
source policy/floorの由来、root identityの選択、時計、独立floorのrollback耐性は配備側の責務。
kernel同期I/O、全Python/Ada/FFIの形式保証、運用policy更新・復旧、正確な計画同意、
世代managed guardとroot sessionへの全体接続はこの変更だけでは完了しない。

## 検証と残る条件

strict typingと実transitionの深さ省略なし有限探索は、完了した段階の順序/回数/終端性を検査する。
途中のOS効果を数学的に証明したものではない。実fileのno-replaceと中断link、
close後FD再利用を検査し、実VMでnormal、誤ったfloor、失効、公開の三境界でSIGKILL、
再実行拒否、非root拒否を確認する。SIGKILLを実電断と同一視しない。
source/package hashと工具・適用範囲は別証跡へ保存する。不変C/全SPARKの証明は反復しない。
