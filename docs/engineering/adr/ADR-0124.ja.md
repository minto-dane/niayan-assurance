# ADR-0124: 保持rootの再検査handoff

状態: proposed-for-review。REQ-161 / HAZ-148 / FAULT-161。

## 背景

非root世代SDKはReinspect_Root_And_Holdで独立観測と実archive/CAS FDを要求する。
root controllerにも保持sessionのObserveがあるが、跨UIDのhandoffは準備だけだった。
準備の成功を再検査の証拠にすることや、返答から期待inodeを作ることはできない。

## 決定

Pkg_Root_Handoff.Reinspectとroot側ReinspectionScopeを追加する。世代、root manifest、
archive、worker、stage、size/entries、今回の期限に、元の展開期限と独立期待root identityを束縛する。
要求224 byteはNIAHRV01、応答40 byteはNIAHRK01と要求全体hashであり、準備とは区別する。
共通境界検査は既存validatorを再利用し、Cの送受信・peer/pidfd・FD処理は一つに保つ。
native Sessionは準備か再検査の一度の送信試行で消費し、操作変更による再利用も拒否する。

rootは起動前の別private channelで同じ子processを認証し、独立に得たReinspectionScopeと
受信全体を一致させる。元のcontroller sessionと物理排他を維持したままObserveを呼ぶ。
受信した値やACKを独立観測、計画同意、現在認可の代用にしない。今回期限や元期限の表示で
失効したsessionを復活させず、失敗後の新規展開・再接続・期限延長を自動実行しない。

## 代替案

既存192 byte要求のgenerationへ別contextのhashを詰めるような意味の流用は行わない。
別のFD受信実装や、同じchannelの曖昧な二回目の準備も追加しない。
旧service/RPCを復活させず、独立観測と保持controllerを使う後継境界へ接続する。

## 影響

wire/APIの追加は内部SDKに限る。新たな公開管理コマンドや常駐daemonはない。
既存の準備request/responseは変えず、受入済みの配置package版もこのSDK変更で進めない。
requesterがroot identityを主張できることは認可ではない。root側の独立scope選択、
current operator/supply/consentと実Observeへのsupervisor接続、全writer排他は別に必要である。

## 検証と残る条件

純粋C validatorに対して、任意の入力/長さ/期限とNULLを含む独立の述語をCBMCで検査する。
unwinding assertion、bounds/pointer、整数/変換/shift、漏洩検査と厳格なGCC静的解析を使う。
これはOS・libsodium・全transport・FFIの形式証明や航空宇宙規格適合ではない。
元validatorも共通helper変更の境界として同じproofで確認し、不変componentの全SPARKは反復しない。

実Ada/C/Python、異なるUID、kernel credentials/pidfdと実FDで準備/再検査を確認する。
誤った元期限/inode、準備用ACK、余分なFD/control、期限、取消、他process、再送を拒否する。
実rootの変化や全寿命認可の取消はこの通信試験の効果ではない。source-bound証跡と残件を保持する。
