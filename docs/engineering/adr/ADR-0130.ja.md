# ADR-0130: 確定状態の具体的readerと予約を保持した更新準備

状態: proposed-for-review。REQ-167 / HAZ-154 / FAULT-167。

確定状態の読み取りをPkg_Generation_Readerへ独立させ、Publisherのread APIも同じ実装へ
委譲する。状態/plan/manifestの共有読み取りはPkg_Generation_Storageへ置く。
照会のために実行認可の仮callbackや弱いManaged engineを作らない。
元のpublication/root/CAS予約、実root/state/descriptor/manifest/terminal journal/retentionと
最終再観測を維持し、初期状態・予約競合・不確定を空catalogにしない。

Pkg_Update_Plannerはその実予約の下で、期待predecessor、native DEB transition、保持intent、
独立site入力と実archive observer、完全なtarget差分の供給map/保持policyを結ぶ。
最終失敗では結果を全消去し、既に保存されたCAS/trust checkpointを自動削除/再実行しない。
これは選択済みtargetの更新準備であり、実行/世代公開/bootの許可ではない。

同じ採用コマンドsocketへread-only dispatcherを追加し、lslppの基本一覧を具体的な非root
native queryへ接続する。管理者配備のroot/state/store/root IDを用い、要求のselectorはpathにしない。
子の元期限とpeer/pidfdを監督し、全native結果と成功終了/EOFを確認してから一つのsealed表示FDを返す。
clientはread-only要求だけでこの別形式を受け入れる。表示の言語と確定catalogの識別を分離する。
未接続の変更要求は拒否する。照会のための旧worker/別PM委譲や同意/認可迂回はない。

配布service/socketは自動起動せず、fixtureや架空catalog設定を同梱しない。
現在は照会と更新準備のsource接続であり、全コマンド互換性、target自動選択、全managed実行、
DEB効果/physical bootまでの完成ではない。照会のCOMMITTEDは確定catalogの項目で、実bootの証明ではない。
[仕様と配備条件](../../../../distribution/native/accepted-catalog.ja.md)を参照。

新規試験コードは追加しない。コンパイル/型検査/挙動・障害試験/形式保証/全面レビューと
POT/MO生成は利用者の最新指示に従いリリース前へ延期した。既存fixtureの接続更新と
accepted/busy/欠損/中断の実カタログ照会、計画中の状態/供給変更の拒否を出荷前に受け入れる。
