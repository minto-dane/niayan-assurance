# RB-003: Commit応答喪失・世代不一致

## 開始条件・封じ込め

同じop IDとplanを保持し、別の更新を割り込ませない。旧/new両媒体をそのまま保存する。

## 読み取りと証拠

Commit_Intent、root.stateの世代、Committed、Active解除のどこまで残ったか読み取る。新世代ならaccepted planとpackage setも照合する。
対象ID、plan、世代、boot、時刻の種別、ログ位置、原本のdigest、実行者と認可を記録します。秘密payloadを一般ログへ貼り付けません。

## 認可された処置

公開済みの判断を別receiptへ変更せず、Reconcile_Terminalで同じ決定を完了する。旧世代かつcommit intentのみの場合も、勝手にrestoreへ転換しない。
実施前に、破壊的操作の対象範囲と回復経路を別の担当者が確認します。未接続のSDKを本番コマンドと取り違えません。

## 終了条件・禁止事項

終了にはAll_Afterと同一decision、Active解除、現在の認可が必要。履歴に一致しない世代は手動の受入判断が必要。
復旧後は新規変更を段階的に再開し、再発監視と障害報告を残します。失敗した証拠は成功ログで上書きしません。
