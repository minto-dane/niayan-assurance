# RB-006: etcd全損・古いsnapshot復元

## 開始条件・封じ込め

旧control planeと古いwriterを隔離し、独立した復旧制御系とバックアップを使う。

## 読み取りと証拠

cluster identity、trust epoch、fence/revision高水位、未解決操作、client/watch cacheを照合する。
対象ID、plan、世代、boot、時刻の種別、ログ位置、原本のdigest、実行者と認可を記録します。秘密payloadを一般ログへ貼り付けません。

## 認可された処置

対象版の正式なetcd復元手順とサイト計画で新しい制御世代を作る。revision/compactionと全client再接続を検査し、古い許可を再使用しない。
実施前に、破壊的操作の対象範囲と回復経路を別の担当者が確認します。未接続のSDKを本番コマンドと取り違えません。

## 終了条件・禁止事項

SDKのdisaster stateが進んだだけで実復元完了にはしない。データと鍵の復元試験、read-only検査、独立承認を必要とする。
復旧後は新規変更を段階的に再開し、再発監視と障害報告を残します。失敗した証拠は成功ログで上書きしません。
