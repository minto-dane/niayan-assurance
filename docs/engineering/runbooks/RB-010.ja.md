# RB-010: バックアップ復元・業務DB移行

## 開始条件・封じ込め

package rollbackを始める前にデータ形式と旧版互換性を確認する。稼働DBを単純なfile copyで戻さない。

## 読み取りと証拠

dataset/lineage、祖先チェーン、鍵、独立コピー、復元試験receipt、RPO/RTOを確認する。
対象ID、plan、世代、boot、時刻の種別、ログ位置、原本のdigest、実行者と認可を記録します。秘密payloadを一般ログへ貼り付けません。

## 認可された処置

DB固有の手順で隔離環境に復元し、整合性と業務検査を行ってから所有権を移す。旧受入状態/監査/失効を混ぜない。
実施前に、破壊的操作の対象範囲と回復経路を別の担当者が確認します。未接続のSDKを本番コマンドと取り違えません。

## 終了条件・禁止事項

複製は誤削除も伝播し得るためバックアップの代替にしない。復元成功とサービス復帰を別々に記録する。
復旧後は新規変更を段階的に再開し、再発監視と障害報告を残します。失敗した証拠は成功ログで上書きしません。
