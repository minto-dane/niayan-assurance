# RB-011: 契約・ソース・証跡の不一致

## 開始条件・封じ込め

新しい配布を止め、old reader/binary/profileと未解決状態を保持する。

## 読み取りと証拠

source subject、共有profile、wire/persistent schema、署名fixture、本番authorityを別々に照合する。
対象ID、plan、世代、boot、時刻の種別、ログ位置、原本のdigest、実行者と認可を記録します。秘密payloadを一般ログへ貼り付けません。

## 認可された処置

設計・移行レビュー後に固定契約を再生成し、全試験と証明を新subjectで実行する。公開fixtureを本番trustへ入れない。
実施前に、破壊的操作の対象範囲と回復経路を別の担当者が確認します。未接続のSDKを本番コマンドと取り違えません。

## 終了条件・禁止事項

古いPASS、緑色のCI画面、手編集のJSONを新バイナリの資格証拠にしない。
復旧後は新規変更を段階的に再開し、再発監視と障害報告を残します。失敗した証拠は成功ログで上書きしません。

## 開発検証の資源超過・強制再起動

途中ログを保存し、完了レポートのない実行は中断と記録する。旧summaryや別unitのPASSを結合して完了扱いにしない。まずGit差分とソース台帳を確認し、重い検証は起動しない。`proof-guard.py`の小規模な停止試験を確認してから、同じPCで1件ずつ再開する。制限到達は失敗であり、自動で上限を増やしたり制限を外したりしない。各プロセスの上限、合計RSSのsample監視、cgroupの総量制限は別の性質として扱う。[ADR-0054](../adr/ADR-0054.ja.md)参照。
