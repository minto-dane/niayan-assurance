# RB-016 Capsuleの破損・権限・隔離異常

新規起動とgrant更新を止め、対象世代・runtime・policy・実行個体・pending操作を保全する。実行中の侵害が疑われる場合はbroker権限を止め、session全体と子孫を隔離/終了し結果を確認する。grant DBの削除だけで既存FDを失効したと扱わない。

管理rootとユーザー/depotのデータを分ける。sealed rootを認証済み入力から新しいcandidateへ再構成し、private dataは無断で初期化/rollbackしない。runtime更新が必要なら新しいapp世代とpolicyで検査する。壊れたcurrent pointerから最高番号を推測採用しない。

AppArmor、seccomp、bwrap、Portal app identity、GPU/ABI cohortが未確認なら起動しない。動かすためにhost HOME、bus、X11、device allを追加しない。Isolated backendが故障した場合はConfined/Nativeへ自動降格しない。

復帰には物理的な停止・正しい入力・正しい権限・プロセス観測・ユーザーデータ互換性が必要。今回の診断成功をその証拠一式と見なさない。
