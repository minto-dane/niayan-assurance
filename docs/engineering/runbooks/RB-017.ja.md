# RB-017 同意・grant・UIの障害

## 最初の封じ込め
新しいgrantの発行を止め、既存の正常な無関係サービスを一括停止しない。対象app/user/generation/instance/boot/request/operationを対応させる。画面表示のエラーを「ユーザーが恒久的に拒否」として保存しない。

## UI・接続障害
owner変更、timeout、無UIでは承認しない。既知のrequestへCloseを試す。記録されたpromptを再起動時に再表示しない。ユーザーの新しい要求には別IDと現在の認証を要求する。

## 資源が渡った可能性がある場合
Portal_Pending/Effect_Pendingは結果不明として保持。まず正確なportal handleまたはoperation IDを照合する。必要な撤回のintentを永続化してから遮断する。Revoke_Pendingの操作を無条件に再送しない。FD/pipe/Doc grantが残る可能性を含め、必要なら正確なcgroupを停止し、その完了を観測する。

## 保存領域の異常
missing/empty/corrupt log、anchorとの不一致、snapshot欠落は新規初期化で補わない。原本・不一致を保全し、独立のcohort復旧を使う。最新らしいコピーの多数決やローカルの最長ログを採用しない。復旧した履歴を根拠にActive leaseを再発行しない。

## 復帰条件
許可の対象と資源の一致、peerとbackendの再認証、失効完了、予算・anchor・ログの一致を確認する。root/カーネルの侵害が疑われる場合は独立rescueへ。秘密値や選択したファイル内容を監査ログへ書かない。
