# 仕様 E-OBS-1: 診断と説明可能な運用

すべての重大操作は、要求ID、plan、root/node/resource、boot/invocation、epoch/token、phase、outcome、
根拠digest、前後の世代、実行時刻の種別を持ちます。生の資格情報・設定payload・環境全体を出力しません。

監視対象は、未解決操作数、長時間保留、予算残量、受入未完世代、破損record位置、CAS欠損、
空きbyte/inode、最後の復元試験、観測の鮮度、期限超過、fencing経路、鍵/証明書期限、contract不一致です。
この文書はメトリクス契約であり、すべての監視exporterが実装済みという意味ではありません。

アラートでは「自動再試行可能」「現状継続で新規変更停止」「対象隔離」「即時人手調査」を分けます。
複数のアラートが同じincidentに由来する場合は相関させますが、相関だけで根拠を削除しません。
ログ転送先の障害時にはローカルの保護された保管と明示した上限を使い、監査を黙って無効化しません。
容量不足で無限に再起動や再送をしてはいけません。

pkg_recoveryctlの出力は観測結果です。`Metadata_Consistent`は、物理ファイル、業務データ、独立アンカーを含む健康宣言ではありません。
対応する退出条件はrunbookで定めます。
