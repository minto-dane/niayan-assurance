# 仕様 E-SEC-1: 脅威・秘密・権限

## 脅威

改ざん・古い署名付き入力の再利用、異なるclusterへの転送、権限役割の混同、部分履歴の切断、
source/vendor不一致、更新されたbyte列に古い試験結果を付けること、symlink/FIFOによる検査混乱、
復旧中の権限緩和、診断への秘密混入を対象にします。
完全に侵害されたkernel/rootが全状態と鍵を置換する攻撃まで、本ソフト単体で防ぐとはしません。

## 最小権限

取得と候補生成は非特権。書込み権限は対象rootと操作を限定します。
管理状態directoryは所有者専用、一般パッケージ計画から監査・信頼・秘密・管理状態を排除します。
既存ファイルの読取り・lock時には非通常ファイル、symlink、hardlink等を拒否する境界を使います。
今回、lock用openへNONBLOCKを加え、特殊入力で属性検査前に待ち続ける経路を狭めました。
未信頼ユーザーが親directoryを変更できる構成や、rootが迂回更新する構成は適格化しません。

## 秘密情報

本番秘密鍵・token・バックアップ復号鍵・BMC資格情報はソース、fixture、コマンドライン、一般ログへ入れません。
環境変数への無制限な継承も避けます。公開fixtureの鍵は人工的な試験用で、本番trust storeへ入れません。
診断はID/digest/phase/outcomeを中心にします。クラッシュdumpは秘密を含み得るため、アクセス・暗号化・保持期限を別管理します。

## 信頼と復旧

署名とTLSは無効化しません。失効世代・受入禁止・監査を、OS復旧と同時に古い状態へ戻しません。
緊急操作でも二者承認、期限、scope、独立監査を必要とし、万能root許可にはしません。
停止条件を解除する変更と、既存正常業務の継続判断を分けます。

## 依存関係とビルド

runtime ABI/native library、ビルドツール、証明器、テストrunnerを記録します。
未認証のバイナリや未固定のCI actionをネットから取り込んで本番成果物を署名しません。
このZIPはMITの自作ソースと従来の依存境界を含みますが、最終配布RPMの依存ライセンス・SBOM・由来は実ビルド時に確定します。
開発frameworkの自己申告結果を本番資格に変換しないため、既存MC_Qualification側の独立署名・subject照合は維持します。
